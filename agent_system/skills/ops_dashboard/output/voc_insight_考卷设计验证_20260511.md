## 4. 递归论证

### 论证 1：为什么卖点绑定不等于验收绑定？

**第一级**：卖点是"对外沟通语言"，考卷是"内部验证语言"。
- 对外："蒸汽+喷水双效清洁"是一个完整的价值主张，用户购买时感知的是一个整体能力。
- 对内：工程团队需要知道如果用户投诉"油污去不掉"，是喷水压力不够还是蒸汽温度不足？

**第二级**：绑定验收会掩盖单能力短板。
- 假设设定"顽固污渍去除率 ≥ 95%"作为绑定指标，通过测试。
- 但实际可能是喷水贡献 90%、蒸汽贡献 5%——蒸汽在顽固污渍场景中形同虚设。
- 绑定验收通过意味着"组合有效"，但无法回答"蒸汽在这个场景中是否必需"。

**第三级**：组合创新的长期维护需要拆分数据。
- 若下一代产品需优化成本，考虑是否可以去掉蒸汽模块——如果没有拆分数据，无法做出数据驱动的决策。

**结论**：卖点绑定是叙事需要，验收拆分是工程需要，两者互补而非互斥。

---

### 论证 2：为什么除螨除菌更适合放在复杂地毯场景？

**第一级**：从用户决策路径看。
- 用户进入"顽固污渍清洁"场景时，搜索关键词是："厨房油污怎么清"、"油烟机清洁"、"重油污地面"。
- 用户进入"复杂地毯清洁"场景时，搜索关键词是："地毯除螨"、"宠物毛发地毯"、"宝宝在地毯上爬"。
- 两个场景的用户意图完全不同，合并会导致场景定义模糊。

**第二级**：从验收可操作性看。
- 顽固污渍场景的验收环境是厨房/餐厅硬质地坪（瓷砖、地板），测试油污类型（食用油、酱汁等）。
- 除螨除菌需要地毯材质作为载体，测试对象是螨虫/细菌，验收标准完全不同。
- 如果放在顽固污渍场景下验收，需要额外搭建地毯测试环境，违背"不可合并"原则的精神。

**第三级**：从竞品对标看。
- 竞品（如戴森、必胜）通常将"地毯深层清洁"与"除螨"作为同一产品线的核心卖点。
- 阿基米德将除螨除菌放在复杂地毯场景下，更符合行业心智，降低用户教育成本。

**结论**：场景分类应以"用户如何想到这个问题"为边界，而非"技术上哪个功能能解决这个问题"。

---

### 论证 3：为什么考卷原则需要"优先级规则"？

**当前 6 项原则**：
1. 不可跳跃：卖点 → 场景 → 考卷 → 指标
2. 不可合并：每个场景独立考卷
3. 必须量化：指标必须是数字
4. 必须可验收：二元判断
5. 必须追溯：每个指标回溯到具体卖点
6. 成本分离：成本在项目 ROI 层面评估

**隐性冲突**：
- 原则 2（不可合并）要求场景独立。
- 原则 5（必须追溯）要求指标回源卖点。
- 当卖点是组合型（如"蒸汽+喷水"），若严格追溯，会导致场景内必须同时包含两项技术的指标——这与"不可合并"精神相矛盾（场景内部实际上合并了两个技术维度）。

**解决方案**：
- 补充原则 2.1："不可合并"指**用户场景**不可合并，而非**技术功能**不可合并。
- 补充原则 5.1：追溯关系允许**多对一**（多个独立指标回溯至同一组合卖点）。
