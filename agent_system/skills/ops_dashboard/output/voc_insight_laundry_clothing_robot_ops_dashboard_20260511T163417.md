## 0. 核心问题回答

**一句话判断**：洗衣叠衣机器人用户真正购买的不是“机器人会把衣服放进洗衣机”或“会折一件衣服”，而是从**散落脏衣 → 正确收集 → 安全洗烘 → 可用折叠/叠放 → 指定区域收纳**的少接管闭环。

当前需求草案已经抓住了三条关键链路：

1. **任务触发链路**：语音、App、智能体定时触发，并反馈任务状态；
2. **洗衣执行链路**：收集脏衣、开门、投放、关门、开机、选择程序、洗烘完成；
3. **叠放整理链路**：从烘干后衣物开始，在平面上折叠并形成可收纳状态。

但从用户视角看，现有指标仍偏向“动作是否完成”，还没有完全覆盖用户最担心的四件事：

- **衣物会不会被弄坏**：缩水、染色、拉扯变形、精细衣物误洗；
- **家庭环境是否适配**：洗衣机/洗烘一体机门型、按键/旋钮/触控差异、洗衣区空间、衣物来源位置；
- **过程是否真的不用盯**：中途卡住、门未关严、程序选错、洗完未烘干、衣物掉落；
- **结果是否能直接进入生活**：叠得是否能放进柜子，是否按家庭成员/品类分堆，是否真的减少家务负担。

因此，建议把 MVP 北极星从“单动作成功率”升级为：

> **有效无人值守洗叠闭环率**：在限定家庭环境、限定衣物品类和限定洗烘设备下，用户发起任务后，无需持续看管，机器人完成脏衣收集、投放洗烘、正确启动、取出折叠/叠放，并且无衣物损伤、无设备异常、无明显漏收/错收，用户认可结果可直接收纳。

## 1. JudgmentUnit：用户判断单元拆解

| 判断单元 | 用户真实判断 | 对需求的翻译 | 运营看板应跟踪 |
|---|---|---|---|
| 多入口触发 | 用户希望“想到就能让它洗”，但更关心它有没有听懂、有没有开始、卡在哪一步 | 语音 / App / 智能体触发都需要任务状态闭环，不只是启动命令 | 唤醒率、意图识别率、端到端触发延迟、状态反馈到达率、误触发率 |
| 家庭成员习惯定时 | 用户不是每天手动下单，而是希望机器人理解家庭节奏 | 定时触发必须结合脏衣量、家庭成员、洗烘时段、噪声/电费/晾晒习惯 | 智能体建议采纳率、定时任务完成率、用户取消率、低价值提醒率 |
| 洗烘设备调研 | 用户不想买回家才发现洗衣机不支持 | 调研问卷不是补充动作，而是购买前兼容性闸门 | 问卷完成率、机型识别成功率、支持/不支持原因、首次校准通过率 |
| 多区域收集脏衣 | 用户最想省的是散落衣物收拾，而不是只处理脏衣篓 | “沙发、卧室等区域收集”要定义可识别区域、可抓取衣物、误收边界 | 区域覆盖率、漏收率、误收率、衣物/非衣物识别准确率、口袋异物提醒 |
| 打开/关闭机门 | 用户不会把这当卖点，但失败会立刻中断信任 | 门型、门把手、门锁、空间余量是适配关键 | 开门成功率、关门锁止确认率、异常恢复率、支持门型覆盖率 |
| 投放并启动程序 | 用户关心“洗得对”，不是只关心“按了开始” | 需要程序选择、重量/衣量、洗涤剂、童锁/门锁、洗烘模式确认 | 正确程序启动率、程序误选率、洗涤剂状态、门锁状态、设备错误码 |
| 洗烘一体限定 | 洗烘一体机能显著降低转移难度，但会缩小可服务家庭范围 | MVP 可先限定洗烘一体机，避免跨设备搬运，但必须把兼容边界前置说清 | 洗烘一体支持率、非支持家庭占比、转化流失原因 |
| 烘干后叠衣 | 用户会用“能不能直接收起来”判断叠衣是否有用 | 叠衣指标不能只算折叠动作，要看品类、平整度、叠放稳定、分类归属 | 折叠成功率、可收纳评分、返工率、品类覆盖、堆叠稳定性 |
| 指定区域收集/叠放/收纳 | 用户希望机器人按家庭规则做事，而不是把衣服堆到一起 | App 指定区域应扩展为家庭成员、品类、收纳点的规则配置 | 指定区域完成率、分类准确率、错放率、用户手动纠正次数 |

## 2. 用户洞察 TOP 10

| 排名 | 用户洞察 | 对产品定义的影响 | 运营判断 |
|---:|---|---|---|
| 1 | **用户买的是“洗叠闭环”，不是单点动作展示** | 成功标准必须跨越触发、收集、投放、洗烘、取出、折叠、叠放 | P0 北极星应是有效无人值守洗叠闭环率 |
| 2 | **兼容性是购买前第一闸门** | 调研问卷要在售前/首装阶段明确支持机型、门型、操作方式和空间要求 | P0 建立机型支持矩阵和不支持原因库 |
| 3 | **脏衣收集是用户价值最高、也是家庭复杂度最高的环节** | 只处理脏衣篓会弱化价值；处理散落衣物必须严格限定区域和误收边界 | P0 先支持固定区域 + 标准脏衣篮，再逐步扩展散落区域 |
| 4 | **衣物损伤风险比动作失败更伤信任** | 需要衣物品类识别、禁洗/精细衣物排除、口袋异物提醒、染色/混洗边界 | P0 指标中必须加入损伤率、误洗率、异常拦截率 |
| 5 | **洗衣机操作不是通用动作，而是设备适配工程** | 前开门/上开门、旋钮/触控/App、门锁/童锁都会影响成功率 | P0 先限定洗烘一体机和已验证机型，不做全机型承诺 |
| 6 | **语音触发指标必要，但不代表任务体验成功** | 语音唤醒 98%、意图识别 95%、延迟 2s 只覆盖入口，还要覆盖任务状态和异常解释 | P0 增加“状态反馈可理解率”和“异常可恢复率” |
| 7 | **折叠 ≥90% 需要质量口径，否则容易变成动作指标** | 折叠成功应定义为平整、方向正确、叠放稳定、可直接收纳 | P0 建立衣物类型 × 折叠质量评分标准 |
| 8 | **家庭成员习惯定时触发只有在低打扰时才成立** | 智能体不能只会提醒洗衣，要判断脏衣量、可洗窗口、家庭睡眠/噪音规则 | P1 跟踪建议采纳率、取消率、打扰反馈 |
| 9 | **收纳是从“有用 Demo”走向“日常家务替代”的关键** | 如果机器人只叠不分类/不放到指定位置，用户仍需二次处理 | P1 做家庭成员/衣物品类/收纳区域规则 |
| 10 | **一次严重事故会抵消多次成功** | 漏水、卡门、夹衣、错洗贵重衣物、错收非衣物都要被设为红线事件 | P0 安全事件、损伤事件、设备异常需作为一票否决指标 |

## 3. 推荐 MVP 边界

### 3.1 MVP 必须包含

| 模块 | MVP 边界 | 用户价值 | 验收重点 |
|---|---|---|---|
| 任务触发 | 支持语音、App 指定区域、智能体定时建议；所有入口统一进入任务状态页 | 用户不用学习复杂入口 | 唤醒率 ≥98%、意图识别 ≥95%、触发延迟 ≤2s、状态反馈完整 |
| 环境/设备确认 | 调研问卷 + 首次校准；先支持明确机型清单内的洗烘一体机 | 防止购买后不可用 | 支持/不支持反馈准确，首次校准可通过 |
| 脏衣收集 | 先支持脏衣篮 + 用户指定的少数固定区域；非衣物/禁洗衣物需提醒 | 省去用户到处捡衣服 | 漏收、误收、抓取失败可记录可复盘 |
| 洗衣机操作 | 开门、投放、关门、开机、选择固定程序、启动洗烘一体模式 | 完成从脏衣到洗烘启动的无人值守链路 | 投放-关门-启动综合成功率 ≥90%，且程序正确 |
| 异常反馈 | 门未关、衣物卡住、机器不支持、衣量异常、程序失败时明确告知用户 | 用户知道是否需要接管 | 异常解释可理解、恢复路径明确 |
| 取出与叠放 | 从洗烘一体机取出干衣，在平面上完成折叠/叠放 | 用户看到最终家务价值 | 折叠成功率 ≥90%，返工率可控，可收纳评分达标 |
| 安全与红线 | 不损伤衣物、不误洗禁洗衣物、不造成设备/水路风险 | 建立家庭信任 | 损伤、漏水、卡门、高危误操作为红线事件 |

### 3.2 可以后置到 V1.1 / V2

| 能力 | 后置原因 | 进入下一阶段的触发条件 |
|---|---|---|
| 跨洗衣机 / 独立洗衣机 + 烘干机转移 | 设备形态差异大，搬运湿衣难度高，失败成本高 | 单一洗烘一体机闭环稳定后扩展 |
| 任意房间散落衣物全屋收集 | 隐私、误收、非衣物识别、路径规划复杂 | 固定区域漏收/误收指标稳定达标 |
| 精细衣物/高价值衣物自动判断 | 衣物标签、材质、护理方式复杂 | 品类识别和用户规则积累足够稳定 |
| 自动加洗涤剂 / 处理多种耗材 | 水路/耗材/残留风险增加 | 洗烘启动链路稳定后再加入 |
| 衣柜/抽屉深度收纳 | 家庭柜体差异大，错放成本高 | 叠放和分类准确率稳定后扩展 |
| 家庭成员级个性化分类 | 需要视觉、标签或用户规则长期校准 | 家庭使用数据足够后再做动态优化 |

### 3.3 不建议首版承诺

| 不建议承诺项 | 原因 |
|---|---|
| 支持所有洗衣机/烘干机 | 门型、控制面板、程序逻辑、空间差异太大，容易拖垮首发体验 |
| 自动处理所有衣物品类 | 真丝、羊毛、内衣、深浅混洗、带配件衣物都有损伤风险 |
| 完全无需用户前置规则 | 家庭脏衣习惯差异大，首版必须允许用户设置禁区、禁洗、收纳规则 |
| 从任意杂乱环境准确判断脏衣 | 地毯、被子、玩具、毛巾、宠物用品等容易混淆 |

## 4. 运营看板指标架构

### 4.1 北极星指标

**有效无人值守洗叠闭环率**

定义：用户通过语音、App 或智能体发起任务后，机器人在限定环境内完成指定脏衣收集、洗烘一体机投放与正确启动、洗烘完成后的取出折叠/叠放；期间用户无需持续看管，无衣物损伤、无误洗、无设备异常，最终结果可直接收纳。

### 4.2 指标分层

| 看板层级 | 指标 | 建议门槛 / 方向 | 运营动作 |
|---|---|---:|---|
| 战略层 | 有效无人值守洗叠闭环率 | MVP 家庭试点 ≥80% 起步，逐步到 ≥90% | 判断是否扩大试点/进入量产评审 |
| 战略层 | 用户主动时间 | 单次任务 ≤3–5 分钟配置/确认 | 减少确认步骤，优化状态反馈 |
| 触发层 | 语音唤醒率 | ≥98%（5m 内按输入口径） | 优化唤醒词和远场麦克风 |
| 触发层 | 意图识别准确率 | ≥95% | 增加洗衣场景语料和二次确认 |
| 触发层 | 端到端触发延迟 | ≤2s | 优化任务入口链路 |
| 触发层 | 任务状态反馈到达率 | ≥99% | 所有入口展示同一状态 |
| 兼容层 | 问卷完成率 / 支持判定准确率 | 越高越好；误判为红线 | 维护机型支持库，减少售前流失 |
| 兼容层 | 首次校准通过率 | ≥90%（已支持机型） | 改善首装引导和校准工具 |
| 收集层 | 指定区域衣物识别召回 | ≥95%（限定品类） | 补训练样本，优化区域规则 |
| 收集层 | 误收率 / 非衣物误抓 | 接近 0 | 加强禁区、非衣物识别、确认机制 |
| 洗衣层 | 投放-关门-启动综合成功率 | ≥90%（输入已有核心指标） | 拆解开门、投放、关门、程序选择失败原因 |
| 洗衣层 | 正确程序启动率 | ≥95% | 固定程序模板，减少自由选择 |
| 洗衣层 | 门锁/水路/设备错误率 | 越低越好，异常必须可解释 | 建立设备错误码映射和客服 SOP |
| 折叠层 | 衣物折叠成功率 | ≥90%（输入已有目标） | 按 T 恤、裤子、毛巾、内衣等品类拆解 |
| 折叠层 | 可收纳评分 / 返工率 | 返工率持续下降 | 优化折叠模板、展开/抖散动作、堆叠稳定 |
| 安全层 | 衣物损伤率 / 误洗率 | 0 作为目标 | 禁洗识别、材质规则、用户确认 |
| 安全层 | 高危设备事件 | 0 | 卡门、漏水、过载、门锁异常全部进入红线审计 |
| 运营层 | 客服工单率 / 上门校准率 | 按试点周追踪 | 识别机型/家庭环境适配问题 |
| 运营层 | D7/D30 复用 | 持续提升 | 判断是否从新鲜感转为日常刚需 |

## 5. 当前需求指标的校正建议

| 当前需求 / 指标 | 保留判断 | 需要补充的口径 |
|---|---|---|
| 语音唤醒率 ≥98%（5m 内） | 保留，适合作为入口指标 | 同步增加误唤醒率、任务确认率、状态反馈率 |
| 意图识别准确率 ≥95% | 保留，适合作为入口指标 | 增加“区域/衣物/时间”槽位识别准确率 |
| 端到端任务触发延迟 ≤2s | 保留，证明入口顺畅 | 不应被误读为任务链路体验指标 |
| 调研问卷收集洗衣机/烘干机信息 | 应升级为售前兼容性闸门 | 问卷后必须输出支持/不支持原因、推荐配置、首装校准要求 |
| “所有脏衣篓衣服放入滚筒-关闭机门-开机-选择程序并完成启动” ≥90% | 保留，但要拆分子指标 | 明确定义“所有衣服”的来源、衣量上限、衣物品类、程序正确性、异常恢复 |
| 洗衣结束后启动烘干（暂定洗烘一体机） | MVP 合理，可降低跨设备转移难度 | 必须在前台明确只支持洗烘一体机或已验证组合，不泛化承诺 |
| 衣物叠放 ≥90% | 保留，但需要质量评分 | 折叠成功应包括展开、识别、折叠、堆叠稳定、可收纳、返工率 |
| App 指定区域收集、叠放、收纳 | 是日常价值关键 | 要从“区域”扩展到家庭成员/衣物品类/禁区/收纳点规则 |
| 智能体按习惯定时触发 | 是长期差异化方向 | 先从建议触发做起，追踪采纳率/取消率，避免低价值打扰 |

## 6. P0 / P1 / P2 行动优先级

### P0｜立项与 MVP 试点前必须锁定

| 行动 | 负责人建议 | 验收标准 |
|---|---|---|
| 定义首版支持环境：洗烘一体机、前开门、可操作面板、固定洗衣区空间 | 产品 + 硬件 + 交付 | 形成机型/空间/门型支持矩阵 |
| 把问卷升级为兼容性判断工具 | 产品 + 用户研究 + 数据 | 用户提交后明确支持/不支持、原因和下一步 |
| 锁定首版衣物范围和禁洗规则 | 产品 + 质量 + 法务/安全 | 精细衣物、高价值衣物、带异物衣物有拦截策略 |
| 建立端到端任务状态机 | 产品 + 软件 | 每一步有状态、失败原因、恢复动作和用户可见反馈 |
| 拆解“投放-关门-启动 ≥90%”为子指标 | 产品 + 测试 | 开门、投放、关门、启动、程序选择分别可定位失败 |
| 建立折叠质量评分体系 | 产品 + 算法 + 用户研究 | 不同衣物品类有可收纳评分和返工判定 |
| 建立红线事件审计 | 质量 + 安全 + 售后 | 衣物损伤、漏水、卡门、误洗、设备异常必须逐单复盘 |

### P1｜封闭家庭试点 4–8 周内

| 行动 | 触发条件 | 目标 |
|---|---|---|
| 扩展指定区域收集能力 | 脏衣篮闭环稳定后 | 从“处理篮子”升级到“帮我找衣服” |
| 做家庭成员/衣物品类分类规则 | 折叠与叠放稳定后 | 降低用户二次整理负担 |
| 优化智能体定时建议 | 用户复用达到每周多次 | 从用户主动触发转为低打扰主动建议 |
| 建立客服/售后失败原因库 | 试点出现足够失败样本 | 快速定位机型、衣物、环境、算法问题 |
| 引入洗涤剂/耗材状态提示 | 启动链路稳定后 | 防止“启动了但洗不好”的体验断点 |

### P2｜产品化扩展阶段

| 行动 | 目标 |
|---|---|
| 支持独立洗衣机 + 烘干机跨设备搬运 | 扩大可服务家庭范围 |
| 支持更多门型、按键/旋钮/触控面板 | 降低兼容性流失 |
| 做衣柜/抽屉深度收纳 | 从“叠好”升级到“放好” |
| 做跨家庭成员习惯学习 | 提升长期使用粘性 |
| 与洗衣机品牌或智能家居平台打通 | 降低物理按键操作失败率 |

## 8. 证据边界与数据能力声明

本节点输入是一段**洗衣叠衣服场景需求草案**，不是原始 VOC 评论池、用户访谈、竞品实测或质量反馈数据。因此，本报告属于**需求草案的用户洞察化与运营看板化**，不是基于样本统计的定量结论。

已能确定的内容：

- 用户价值主线应从“单点动作成功”升级到“有效无人值守洗叠闭环”；
- 当前入口指标（唤醒率、意图识别、触发延迟）必要但不足，需要接入任务状态、异常恢复和结果质量；
- 洗烘一体机作为 MVP 限定是合理的降复杂度策略，但必须在售前兼容性里透明表达；
- 洗衣链路需要加入衣物损伤、误洗、误收、设备异常等红线指标；
- 折叠 ≥90% 需要可收纳质量口径，不能只算动作完成。

建议下一步补充数据：

1. 10–30 户家庭洗衣习惯访谈：脏衣来源、收纳规则、家庭成员差异、禁洗衣物；
2. 主流洗烘一体机/洗衣机门型与面板操作调研：形成支持矩阵；
3. 衣物品类样本库：T 恤、裤子、毛巾、内衣、衬衫、儿童衣物、易损衣物；
4. 家庭试点日志：每一步失败原因、用户接管原因、返工原因；
5. 折叠质量盲评：用户是否认为“可以直接放进柜子”。

## 9. 给父流程的节点交付结论

- 已以 `ops_dashboard` 的运营看板方式完成 `voc_insight` 节点：把洗衣 / 叠衣需求草案收敛为**用户价值判断、MVP 边界、指标看板、优先级行动和证据边界**。
- 关键结论：首版不应承诺全家庭、全机型、全衣物品类自动洗叠；应先在**限定洗烘一体机 + 固定洗衣区 + 明确衣物品类 + 可解释状态机**下打穿闭环。
- 推荐北极星：**有效无人值守洗叠闭环率**。
- 当前需求中的 `语音唤醒率 ≥98% / 意图识别 ≥95% / 触发延迟 ≤2s / 投放-关门-启动 ≥90% / 折叠 ≥90%` 可保留，但需要补充兼容性、损伤、误洗、异常恢复、返工率和可收纳质量口径。
- 下一步建议：优先建立机型支持矩阵、端到端任务状态机、衣物禁洗/误收规则、折叠质量评分与红线事件审计。
