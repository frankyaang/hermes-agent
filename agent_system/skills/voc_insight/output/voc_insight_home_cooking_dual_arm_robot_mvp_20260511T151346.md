## 2. 输入信号与洞察框架

**源材料**：从用户价值、用户体验验证标准和运营优先级角度，分析家庭自主做饭双臂机器人应如何定义 MVP。

该输入不是传统评论/VOC表，而是一个**产品定义型 VOC 问题**：用户真正想知道的不是“机器人能做多少菜”，而是“什么样的最小闭环能够证明家庭自主做饭机器人值得继续投入”。

本次采用 `voc_insight` 的三轴框架：

1. **用户价值**：用户是否愿意为“少操心、少动手、更安全、更稳定地吃上一顿饭”付出厨房空间、准备成本和信任成本。
2. **用户体验验证标准**：是否能用可观测指标证明它不是演示玩具，而是可被家庭信任的服务。
3. **运营优先级**：先验证高频、可控、可复现的闭环，再扩展菜谱、环境和全自主能力。

---

## 3. 核心洞察结论

### 3.1 MVP 不应定义为“全自主家庭厨师”

家庭自主做饭双臂机器人的 MVP 如果一开始追求“任意厨房、任意食材、任意菜谱、全流程无人参与”，会同时踩中四个高风险点：开放环境感知、刀具/热源安全、食材不确定性、口味个性化。这样的 MVP 更像科研展示，难以证明家庭用户价值。

**更合理的 MVP 定义**：

> 在标准化家庭厨房与预置食材/厨具约束下，双臂机器人能够安全、稳定地完成 2-3 个高频低风险家常烹饪闭环；用户只需一次性准备/确认，机器人完成取放、倒入、搅拌、翻面/翻炒、火候控制、装盘和基础收尾，并在异常时可解释、可暂停、可恢复。

一句话概括：**MVP 是“可信任的半标准化做饭助手”，不是“无所不能的机器人厨师”。**

### 3.2 MVP 的用户价值北极星

MVP 的北极星不应是“能做多少道菜”，而应是：

> 在一个真实高频家庭场景中，让用户少操心、少站在灶台前，同时得到安全、可入口、稳定复现的一餐/一道主菜。

因此首个 MVP 应验证三件事：

1. **注意力节省**：用户不用全程盯锅，至少释放 15-20 分钟连续注意力。
2. **风险降低**：热油、热锅、重复搅拌、端取等高负担动作由机器人承担，但安全边界清晰。
3. **结果稳定**：菜品不是偶然成功，而是在同一约束下可重复成功。

### 3.3 双臂价值必须被验证，而不是作为硬件卖点存在

如果 MVP 只做单臂也能完成的“按按钮加热/搅拌”，它无法证明双臂机器人价值。首版场景应包含明确的双臂必要性，例如：

- 一只手稳定锅/碗/锅盖，另一只手倒入、翻炒或搅拌。
- 一只手持容器，另一只手用刮刀辅助倒净。
- 一只手开合/扶持，另一只手完成取放或装盘。
- 一只手处理热源附近动作，另一只手执行安全隔离/工具切换。

**判定原则**：若一个 MVP 场景不能产生“没有双臂就明显更慢、更不稳或更不安全”的用户可感知差异，应降级或更换场景。

## 4. 推荐 MVP 范围

### 4.1 推荐定位：半标准化 meal-kit 型家庭烹饪助手

| 维度 | MVP 建议 |
| --- | --- |
| 使用环境 | 标准台面 + 标准电磁炉/封闭热源 + 标准锅具/夹具/容器位 |
| 食材形态 | 预清洗、预切、预称重、分盒/分袋食材；不处理随机散装食材 |
| 首批菜谱 | 2-3 个高频、低风险、步骤稳定的家常菜/轻食，如炒蛋类、炒蔬菜类、煎烤/加热类 |
| 用户参与 | 开始前摆放食材并确认计划；异常时授权；无需全程盯守 |
| 机器人任务 | 识别容器位、取放、开合、倒入、搅拌/翻炒、火候/时间控制、装盘、提示收尾 |
| 安全边界 | 不用开放明火，不做生硬骨切割，不做复杂刀工，不在无人监管下处理高风险油炸 |

### 4.2 MVP 必须包含的能力

| 能力层 | 必须做到 | 为什么是 MVP 必需 |
| --- | --- | --- |
| 安全控制 | 急停、热区识别、碰撞/夹伤防护、失败自动降级 | 家庭用户信任的前置条件 |
| 任务编排 | 用户可看到“今天做什么、分几步、何时需要确认” | 降低黑箱感，提升可控感 |
| 双臂操作基元 | 抓取、扶持、倒入、刮取、搅拌、翻面/翻炒、装盘 | 验证双臂硬件价值 |
| 火候/时间控制 | 可对接电磁炉/智能锅具，能按菜谱控制温度和时长 | 烹饪结果稳定的基础 |
| 异常恢复 | 食材没放好、锅具偏移、粘锅/溅出、识别失败时可提示用户 | MVP 不能只在理想条件下工作 |
| 可清洁设计 | 接触食物部件可拆洗，台面污染可提示 | 家庭持续使用的运营成本 |

### 4.3 MVP 明确不做的范围

| 暂不纳入 | 原因 |
| --- | --- |
| 任意菜谱生成与开放式烹饪 | 变量过多，难以验证核心用户价值 |
| 随机食材识别、清洗、复杂切配 | 安全与感知难度高，容易拖垮 MVP |
| 开放明火/高温油炸/复杂肉类熟化 | 安全责任高，不适合首版家庭 MVP |
| 完整厨房清洁、洗碗、垃圾处理 | 是后续生态价值，不是做饭 MVP 的最小闭环 |
| 口味高度个性化 | 需建立基础稳定性后再做 |
| 大规模菜谱库 | 会稀释工程资源，掩盖基础可靠性问题 |

## 5. 用户体验验证标准

MVP 的体验验证应采用“安全门槛 + 任务成功 + 用户价值 + 复用意愿”四层门禁。

### 5.1 P0 安全门槛（不过即停止扩展）

| 指标 | 建议门槛 |
| --- | --- |
| 重大安全事故 | 0 起，包括烫伤、割伤、失控碰撞、火源失控 |
| 急停响应 | 用户触发后 ≤1 秒进入安全停机/降温/撤离状态 |
| 热区/人手靠近识别 | 高风险动作前必须暂停或降速，误放行率为 0 |
| 工具/锅具偏移处理 | 偏移超过阈值时暂停并提示，不盲目继续 |
| 儿童/宠物干扰策略 | 检测到进入危险区域时自动降级或暂停 |

### 5.2 P1 任务成功标准

| 指标 | MVP 验收建议 |
| --- | --- |
| 受控实验成功率 | 单菜谱连续 50-100 次运行成功率 ≥90% |
| 家庭试点成功率 | 10-20 户、连续 2 周试用，目标任务成功率 ≥80-85% |
| 人工介入次数 | 单次烹饪中非计划介入 ≤2 次 |
| 工程师介入 | 家庭试点中不得依赖工程师现场救场 |
| 异常可恢复率 | 常见异常（容器偏移、食材未放、粘锅）≥80% 可通过提示或自动动作恢复 |

### 5.3 P2 用户价值标准

| 指标 | 目标 |
| --- | --- |
| 注意力释放 | 用户无需盯守的连续时间 ≥15-20 分钟，或主动看护时间下降 ≥50% |
| 准备时间 | 用户前置准备/摆放时间 ≤5 分钟 |
| 总时长接受度 | 不超过用户手动做饭基准的 1.5 倍；若更慢，必须换来明显少操心 |
| 复用意愿 | 试点家庭每周主动使用 ≥3 次，且愿意重复同一类场景 |
| 信任评分 | “我敢让它下次继续做这道菜”评分 ≥4/5 |

### 5.4 P3 菜品结果标准

| 指标 | 目标 |
| --- | --- |
| 可入口/口味评分 | 家庭成员评分 ≥3.8/5，且波动可解释 |
| 熟度/温度 | 达到食品安全与目标口感标准，不夹生、不过熟 |
| 一致性 | 同一菜谱多次结果差异小于用户可明显感知阈值 |
| 视觉与装盘 | 不追求餐厅级美观，但不得明显狼藉或影响食欲 |

## 6. 运营优先级

### 6.1 优先级排序

| 优先级 | 事项 | 运营判断 |
| --- | --- | --- |
| P0 | 安全、可停、可控、可解释 | 信任一旦破裂，后续菜谱数量没有意义 |
| P0 | 场景标准化：标准炉具、锅具、容器、食材位 | 先把环境变量压到可运营范围内 |
| P1 | 2-3 个高频闭环菜谱打穿 | 用高复用场景验证真实留存，而不是堆功能 |
| P1 | 双臂操作基元沉淀 | 让每个菜谱都复用抓取/倒入/搅拌/装盘等基元 |
| P1 | 家庭试点数据闭环 | 记录失败原因、人工介入、复用频次、信任评分 |
| P2 | 扩展食材形态与菜谱库 | 只有核心闭环稳定后再扩展 |
| P3 | 完全开放厨房与全自主备菜 | 属于后续平台化阶段，不应放入 MVP |

### 6.2 建议阶段路径

| 阶段 | 目标 | 通过标准 |
| --- | --- | --- |
| MVP-0 实验室闭环 | 标准厨房台架，2 个菜谱，连续稳定运行 | 50-100 次/菜谱，成功率 ≥90%，0 重大安全事故 |
| MVP-1 控制家庭试点 | 10-20 户，meal-kit/预置食材，2 周使用 | 家庭成功率 ≥80-85%，每周主动使用 ≥3 次 |
| MVP-2 扩展验证 | 增加到 5-8 个菜谱，允许少量食材差异 | 失败可解释，用户不因准备/清洁成本放弃 |
| Beta 商业验证 | 绑定耗材/食材包/智能厨具生态 | 留存、复购、服务成本和售后风险可控 |

### 6.3 首批场景推荐

| 场景 | 推荐度 | 理由 |
| --- | --- | --- |
| 预切食材的一锅炒/炒蛋类 | 高 | 高频、步骤短、双臂倒入/搅拌/装盘价值明显 |
| 早餐轻食/煎蛋/加热装盘 | 高 | 用户频次高，容错较高，适合建立信任 |
| 简单煎烤类 | 中 | 结果可量化，但热源与油烟风险需控制 |
| 复杂刀工/多锅并行大餐 | 低 | 不适合 MVP，变量过多 |
| 油炸、明火爆炒 | 低 | 安全和合规风险高 |

## 7. MVP Go / No-Go 判定

### Go 条件

- 用户能在不全程盯守的情况下完成至少 2 个高频菜谱。
- 试点用户明确感知“我少操心/少动手了”，而不是只觉得新奇。
- 安全、失败恢复和清洁成本可运营。
- 双臂动作在关键任务中产生可见价值。
- 数据闭环能持续解释失败并改进下一轮菜谱/动作基元。

### No-Go 信号

- 用户必须全程站旁边监督，注意力没有释放。
- 单次失败会让用户不敢再次使用。
- 每多一道菜都要大量定制工程，无法复用动作基元。
- 做饭后清理/摆放成本超过用户手动做饭节省的时间。
- 双臂只作为展示硬件存在，核心价值可被单臂/智能锅替代。

## 8. 关键风险与待补数据

### 8.1 风险

1. **演示成功 ≠ 家庭可用**：实验室一次成功不能证明家庭连续使用。
2. **过早追求开放能力**：任意食材和任意菜谱会压垮安全与稳定性。
3. **信任成本被低估**：做饭涉及热源和食物入口，用户容错低于普通家电。
4. **准备/清洁成本反噬价值**：若用户前置摆放和后置清洗太麻烦，机器人节省的时间会被抵消。
5. **双臂 ROI 不清晰**：若缺少双臂不可替代任务，产品成本难以被用户理解。

### 8.2 待补数据

- 目标用户分层：忙碌双职工、有孩家庭、老人辅助、厨房新手，谁最痛。
- 目标厨房与价格带：标准厨房空间、可接受设备体积、价格/服务费上限。
- 首批菜系与区域：中式炒菜、早餐轻食、欧美煎烤/意面等优先级。
- 用户对 meal-kit/预切食材的接受度。
- 安全合规要求与家庭保险/责任边界。
- 与智能锅、炒菜机、单臂厨房机器人相比的用户替代/溢价证据。

## 9. 结构化结论摘要

| 维度 | 结论 |
| --- | --- |
| MVP 一句话定义 | 标准化厨房约束下，完成 2-3 个高频低风险家常烹饪闭环的可信任双臂做饭助手 |
| 核心用户价值 | 少操心、少站灶台、更安全、结果稳定，而不是菜谱数量炫技 |
| 首要验证 | 安全 + 注意力释放 + 任务成功率 + 复用意愿 |
| 首批范围 | 预置/预切食材、标准锅具、电磁炉/封闭热源、炒蛋/一锅炒/早餐轻食类 |
| 明确不做 | 任意菜谱、随机食材复杂切配、明火油炸、全厨房清洁、全自主开放环境 |
| 运营策略 | 先打穿 2-3 个高频闭环和动作基元，再扩菜谱与食材自由度 |
| 最大风险 | 安全/信任崩塌，以及准备清洁成本抵消用户价值 |
