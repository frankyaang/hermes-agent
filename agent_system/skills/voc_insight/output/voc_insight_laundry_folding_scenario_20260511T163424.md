## 2. 结论先行

**核心洞察**：洗衣/叠衣场景的用户价值不是“机器人能按下洗衣机按钮”，而是让用户相信：**散落脏衣能被找到、该洗的衣服能被正确处理、洗烘设备能被安全启动、洗完后衣服能被整理成可收纳状态，并且异常时用户不会被迫重新接管全流程。**

因此，该场景不应只按“语音触发 → 投放洗衣机 → 选择程序 → 叠衣”定义，而应定义为一条闭环：

> **触发任务 → 判断家庭/设备是否可接管 → 收集脏衣 → 分拣与预检 → 投放并启动洗烘 → 监控异常 → 取出干衣 → 平面折叠 → 叠放/收纳/交付 → 反馈完成状态。**

当前输入已覆盖“触发、设备问卷、投放启动、平面折叠”四段，但还缺四个会直接影响用户信任的关键段：

1. **脏衣识别与误拾取边界**：什么衣物可拿、什么不能拿、口袋异物/贵重物/湿污衣物如何处理。
2. **分拣与程序匹配**：深浅色、材质、内衣/外衣、床品、精细面料是否混洗；洗衣程序由谁决定。
3. **洗烘完成后的取出与转运**：材料写了“整套从烘干机拿出来”，但未定义机器人如何开门、取出、避免掉落、处理高温/潮湿。
4. **叠放后的完成态**：用户不是只要“折一下”，而是要“能按家庭习惯放好/交付到指定位置”。

## 3. JudgmentUnit：用户判断单元拆解

| ID | 源材料信号 | 用户真实判断 | 产品任务翻译 | 定义输入 |
|---|---|---|---|---|
| JU-01 | 支持语音触发及反馈任务状态 | 用户不想为了让机器人洗衣再打开复杂入口；但必须知道它有没有听懂、有没有开始做 | 多入口触发 + 即时确认 + 状态可追踪 | 语音 / App / 智能体定时都应落到同一个任务状态机，避免三个入口三套逻辑 |
| JU-02 | App 支持指定区域收集、叠放、收纳 | 用户默认衣物会分散在卧室、沙发、浴室、脏衣篮附近；“指定区域”比“全屋乱找”更可信 | 区域化任务规划 + 可排除区域 + 收纳目标位 | MVP 应先做指定区域 / 固定脏衣篮 / 固定平面，不承诺任意房间和任意衣物 |
| JU-03 | 根据家庭成员习惯定时触发 | 洗衣是周期性家务，用户希望它自动排进生活节奏，但不能在不合适时间打扰家庭 | 习惯学习 + 时间窗 + 成员权限 + 安静时段 | 定时触发必须绑定“可执行条件”：衣物量、家里是否有人、洗衣机空闲、是否夜间噪音限制 |
| JU-04 | 调研问卷收集洗衣机/烘干机信息 | 用户最担心的是家里设备能不能被机器人实际操作，而不是机器人理论能力 | 设备兼容性门禁 | 问卷只是第一层；还需要实机验证：门型、把手、按钮/旋钮、程序选择方式、IoT/API 能力 |
| JU-05 | 从沙发、卧室等区域收集脏衣 | 用户希望减少弯腰、走动、到处捡衣服和催家人的负担 | 脏衣识别、可拾取判断、路径收集 | 必须定义误拾取红线：干净衣、正在穿/挂起衣、贵重物、带口袋异物衣物不得混入 |
| JU-06 | 打开/关闭洗衣机门、投放衣物 | 用户真正关心的是不损坏门、不夹衣、不漏水、不把衣服卡在门缝 | 门体操作 + 负载投放 + 关门确认 | 不能只统计“把衣服放进去”；需单独验证门锁、门缝夹衣、负载均匀、滚筒内残留 |
| JU-07 | 启动洗衣机并选择程序 | 用户不希望机器人洗坏衣服，也不希望选错程序导致返工 | 洗涤程序匹配 | MVP 可先固定“默认混合洗 / 标准洗烘一体”程序；精细分拣和特殊材质后置 |
| JU-08 | 洗衣结束后启动烘干 | 用户希望洗完不用记得转移，但洗烘链路涉及热、湿、门锁和衣物皱褶 | 洗烘状态监控 + 干燥完成判断 | 洗烘一体机是合理 MVP 边界；独立洗衣机+烘干机转运应作为后续阶段 |
| JU-09 | 平面上对平铺衣服折叠 | 用户会用“是否像人整理过”判断机器人价值；叠衣质量很可见 | 干衣取出、摊平、识别衣物类型、折叠、叠放 | “≥90%”必须限定衣物类型与判定标准，例如 T 恤/毛巾/长裤/睡衣，不应覆盖任意衣物 |
| JU-10 | 按同样结构梳理需求 | 用户需要的是可进入产品定义/验收的结构，而不是单纯能力罗列 | 需求结构化 + 指标化 + 风险门禁 | 输出应按任务阶段拆解用户价值、P0/P1/P2范围、验收指标、缺失证据 |

## 4. 洗衣/叠衣场景的用户任务链

### 4.1 建议完整任务链

1. **触发任务**：语音 / App / 自动日程触发，并反馈任务是否已创建。
2. **设备与环境确认**：确认洗衣机/烘干机类型、门型、控制方式、可达路径、可操作高度、是否空闲。
3. **区域收集**：在用户指定区域找脏衣，排除禁区、干净衣、易损物和非衣物。
4. **分拣与预检**：识别颜色/材质/衣物类型/口袋异物/特殊污渍，决定是否进入本次任务。
5. **投放洗衣机**：开门、放衣、避免夹衣、确认滚筒内位置、关门、锁门状态确认。
6. **启动洗烘程序**：选择程序，启动，确认设备进入运行状态。
7. **过程监控与异常反馈**：门未锁、水位异常、设备报错、衣物量过载、程序中断时可解释、可暂停、可让用户接管。
8. **洗烘完成处理**：确认干燥完成，开门散热，取出衣物，转运到折叠平面。
9. **衣物折叠**：按衣物类型识别、摊平、折叠、堆叠。
10. **叠放 / 收纳 / 交付**：放入指定篮、收纳格、床面或衣柜外部指定区域，并反馈完成。

### 4.2 MVP 边界建议

**MVP 推荐定义**：

> 在一个已验证兼容的家庭环境中，机器人可在用户指定区域收集标准脏衣，投放至前置式洗烘一体机，启动预设洗烘程序，并在衣物干燥后对标准衣物在固定平面完成折叠与叠放。

**MVP 不应承诺**：任意洗衣机/烘干机、独立洗烘机自动转运、任意衣物分拣、精细面料护理、口袋异物 100% 检出、直接入柜收纳、全屋无边界搜索。

## 5. 按“同样结构”的场景需求梳理

### 5.1 触发任务

| 维度 | 用户需求 | P0 产品定义 | 建议指标 |
|---|---|---|---|
| 语音触发 | 用户一句话发起，不想复杂设置 | 支持“开始洗衣 / 收一下卧室脏衣 / 把烘干衣服叠好”等常用意图 | 语音唤醒率 ≥98%（5m 内）；意图识别准确率 ≥95%；端到端任务创建延迟 ≤2s |
| App 触发 | 用户要可控地指定区域、任务范围和完成位置 | 支持选择收集区域、洗衣机、折叠平面、叠放位置 | App 任务参数完整率 ≥98%；用户撤销/修改可在任务执行前生效 |
| 智能体定时 | 用户希望它按家庭节奏自动提醒或执行 | 支持基于家庭成员习惯、衣物量、设备空闲状态和安静时段触发 | 自动触发误打扰率 ≤2%；可执行条件满足后再启动 |
| 状态反馈 | 用户要知道“它听懂了吗、做到哪了、要不要我管” | 统一任务状态：已创建 / 收集中 / 待投放 / 洗烘中 / 待折叠 / 已完成 / 需接管 | 关键状态反馈延迟 ≤3s；异常必须给出原因与下一步选择 |

### 5.2 确定环境和设备类型

| 维度 | 用户需求 | P0 产品定义 | 建议指标 |
|---|---|---|---|
| 设备兼容 | 用户担心家里机器不能被机器人真实操作 | 问卷收集品牌、型号、门型、控制方式、安装位置、可达空间 | 设备信息采集完整率 ≥95% |
| 实机验证 | 问卷不足以证明能操作 | 首次建图/标定时验证开门、关门、按钮/API、程序启动、门锁状态反馈 | 兼容性判断准确率 ≥98%；不支持原因可解释 |
| 洗烘边界 | 洗烘一体机比独立洗衣机+烘干机更适合首版 | MVP 先支持前置式洗烘一体机；独立烘干机转运后置 | MVP 兼容机型名单覆盖目标试点家庭 ≥80% |
| 安全边界 | 用户不能接受夹衣、漏水、误启动 | 门锁、夹衣、过载、儿童/宠物靠近时降级 | 高风险误放行 0；门未确认关闭不得启动 |

### 5.3 衣物收集

| 维度 | 用户需求 | P0 产品定义 | 建议指标 |
|---|---|---|---|
| 指定区域收集 | 用户希望减少到处捡衣服，但不希望机器人乱翻家 | 先支持卧室地面、沙发边、脏衣篮周边等用户指定区域 | 指定区域覆盖成功率 ≥90%；禁区进入 0 |
| 脏衣识别 | 用户不想干净衣、抱枕、毛巾、玩具被误拿 | 识别可拾取衣物 vs 非衣物 / 干净挂置衣物 / 易损物 | 误拾取率 ≤2%；非衣物误投放 0 |
| 口袋与异物 | 用户最怕洗坏证件、纸巾、耳机 | 对明显硬物/重物/异常鼓包做风险提示 | 高风险异物提示召回率 ≥90%（先限定大件/硬物） |
| 分拣策略 | 用户担心混洗造成掉色、缩水、损伤 | MVP 可先让用户选择“本次只处理普通日常混洗衣物”；精细分拣后置 | 特殊衣物识别后进入“待用户确认”而非自动投放 |

### 5.4 衣物清洗与洗烘启动

| 阶段 | 用户需求 | P0 产品定义 | 建议指标 |
|---|---|---|---|
| 开门 | 不损坏机器、不碰撞、不夹手 | 识别门把手/开门方向，低速力控开门 | 开门成功率 ≥95%；异常力停机 100% |
| 投放 | 衣服完整进入滚筒，不挂门、不掉地、不堵门缝 | 分批投放、滚筒内视觉确认、门缝检查 | 投放成功率 ≥90%；门缝夹衣率 ≤1% |
| 关门 | 门要关严，启动前确认锁门 | 关门后检测门锁/门缝/设备状态 | 关门确认成功率 ≥98%；门未锁启动 0 |
| 程序选择 | 不洗坏衣服，不用用户返工 | MVP 使用预设标准程序或 App/API 联动；特殊程序需用户确认 | 程序选择正确率 ≥95%；错误程序导致返工 0 |
| 启动与监控 | 用户希望它真的启动成功且有反馈 | 启动后确认设备进入运行状态，并同步预计完成时间 | 启动确认成功率 ≥98%；异常反馈 ≤30s |

> 原输入中的指标“成功将所有脏衣篓衣服放入滚筒-关闭机门-开机-选择程序并完成启动机器的操作 ÷ 总次数 ×100% ≥90%”建议拆成子指标。否则一个总成功率无法定位失败来自开门、投放、关门、程序还是启动确认。

### 5.5 洗烘完成与衣物转运

| 维度 | 用户需求 | P0 产品定义 | 建议指标 |
|---|---|---|---|
| 完成判断 | 用户不想自己记得去看洗完没 | 读取设备完成状态，确认门可打开、温度/湿度可处理 | 完成状态识别准确率 ≥98% |
| 取出干衣 | 衣服不能掉地、不能遗留、不能烫手/潮湿 | 分批取出，检测滚筒残留，转运到折叠平面 | 滚筒残留率 ≤2%；掉落污染率 ≤1% |
| 干燥质量 | 用户不接受折叠潮湿衣物 | 湿度/重量/触感或设备状态判断是否可折叠 | 潮湿衣物误折叠率 ≤2%；未干提示准确 |

### 5.6 衣物叠放

| 维度 | 用户需求 | P0 产品定义 | 建议指标 |
|---|---|---|---|
| 标准衣物折叠 | 用户希望看到可见结果，而不是一堆皱衣 | 先支持 T 恤、毛巾、长裤、睡衣等标准衣物在固定平面折叠 | 标准衣物折叠成功率 ≥90% |
| 衣物摊平 | 折叠前要铺平，否则质量不可控 | 从衣堆中分离单件、识别正反/袖口/裤腿，摊平 | 单件分离成功率 ≥85%；摊平后可折叠率 ≥90% |
| 叠放质量 | 用户会用整齐度判断是否值得继续用 | 折叠后堆叠稳定，按类别/家庭成员可选分堆 | 堆叠倒塌率 ≤2%；用户可接受评分 ≥4/5 |
| 异常衣物 | 内衣、袜子、衬衫、裙装、厚外套难度高 | 先识别并放入“待人工处理”篮，不强行折叠 | 不支持衣物误折叠率 ≤5%；损伤 0 |

## 6. Top 用户洞察与产品定义输入

| 排名 | 洞察结论 | 对产品定义的直接建议 |
|---:|---|---|
| 1 | 用户购买的是“洗衣家务从脑子里消失”，不是机器人会操作洗衣机 | KPI 要加入人工介入次数、注意力释放、任务闭环完成，而不只统计单步成功率 |
| 2 | 触发体验必须轻，但任务控制必须清楚 | 语音、App、定时触发共用任务状态机；每一步能暂停、取消、接管 |
| 3 | 设备兼容是第一道信任门槛 | 问卷只能做预筛；必须增加实机标定与兼容清单，不支持时明确原因 |
| 4 | 衣物收集最大的风险是“拿错东西” | 必须定义可拾取/不可拾取边界，禁区、干净衣、非衣物、口袋异物是 P0 风险 |
| 5 | 洗衣程序选择比启动按钮更影响用户信任 | 首版用标准程序和用户确认降低洗坏衣服风险，复杂分拣后置 |
| 6 | 洗烘一体机是合理 MVP 边界 | 独立洗衣机+烘干机转运复杂度高，应放到 P1/P2 阶段 |
| 7 | 叠衣是满意度显性点，但不能用“任意衣服 ≥90%”表述 | 折叠指标必须按衣物类别、材质、尺寸和质量标准拆分 |
| 8 | 异常处理决定用户是否敢让它自动运行 | 门未锁、夹衣、潮湿、设备报错、异物、儿童/宠物靠近必须可解释、可降级 |
| 9 | “家庭成员习惯”不是简单定时器 | 需要结合衣物量、安静时段、设备空闲、家庭成员权限和收纳偏好 |
| 10 | 收纳/交付是用户心里的完成态 | MVP 可先放到指定篮/床面/收纳台；直接入柜需后置，并定义家庭成员分类 |

## 7. P0 / P1 / P2 范围建议

### P0：首版必须打穿

- 指定区域 / 固定脏衣篮收集，不做全屋无边界搜索。
- 兼容前置式洗烘一体机，完成开门、投放、关门、启动、状态确认。
- 支持标准日常混洗衣物，特殊衣物进入待确认。
- 语音 / App / 定时触发统一到同一任务状态机。
- 关键异常可解释、可暂停、可让用户接管。
- 洗烘完成后取出干衣，转运到固定折叠平面。
- 对标准衣物完成折叠与叠放。

### P1：体验增强与可用性扩展

- 家庭成员习惯学习：时间窗、衣物量、房间优先级、安静时段。
- 口袋异物 / 纸巾 / 硬物风险检测增强。
- 常见衣物类型分拣：深浅色、毛巾、床品、日常衣物。
- 支持独立洗衣机与烘干机之间的短距离转运，但需限定设备布局。
- 折叠后按家庭成员 / 类别分堆。

### P2：后续平台能力

- 任意房间开放式收集。
- 精细面料护理、衬衫、裙装、厚外套等复杂衣物折叠。
- 直接入柜收纳、抽屉开合、衣柜分区识别。
- 多品牌多形态洗衣机/烘干机深度兼容。
- 基于历史穿着、天气、家庭日程的主动洗护建议。

## 8. 建议验收指标重构

| 指标组 | 建议指标 | 说明 |
|---|---|---|
| 触发 | 语音唤醒率 ≥98%；意图识别 ≥95%；端到端任务创建 ≤2s | 保留原指标，但只代表入口体验 |
| 状态机 | 关键状态反馈 ≤3s；异常反馈 ≤30s | 用户放心的关键不是“触发快”，而是“过程可见” |
| 设备兼容 | 兼容判断准确率 ≥98%；实机标定通过后再开放自动执行 | 防止问卷误判导致现场失败 |
| 收集 | 指定区域脏衣召回率 ≥90%；误拾取率 ≤2%；禁区进入 0 | 收集成功必须包含“不拿错” |
| 预检 | 高风险异物提示召回率 ≥90%（限定大件/硬物）；特殊衣物待确认 | 不建议首版承诺 100% 口袋异物识别 |
| 投放启动 | 开门成功 ≥95%；投放成功 ≥90%；关门锁定确认 ≥98%；程序选择正确 ≥95% | 拆分原总指标，便于定位问题 |

| 折叠 | 标准衣物折叠成功 ≥90%；堆叠稳定失败 ≤2%；用户可接受评分 ≥4/5 | 必须限定衣物类别与质量标准 |
| 用户价值 | 单次任务人工介入 ≤1 次；用户主动复用率；家务时间/走动/弯腰次数下降 | 证明不是技术演示，而是家务减负 |

## 9. 风险与待补证据

### 9.1 当前高风险点

1. **分拣缺失风险**：如果不区分颜色、材质、内衣外衣、床品，用户会担心洗坏或混洗不卫生。
2. **误拾取风险**：沙发、卧室等区域存在干净衣、儿童玩具、抱枕、充电线、证件耳机等，误投放会直接破坏信任。
3. **设备操作风险**：门体、按钮、旋钮、触控屏、童锁、门锁状态和报错机制各品牌差异大。
4. **独立洗烘转运风险**：从洗衣机转烘干机涉及湿衣重量、掉落、门位、路径和设备高度，复杂度高于洗烘一体机。
5. **叠衣泛化风险**：衣物柔性体差异大，若不限定衣物类型，“≥90%”容易变成实验室指标。
6. **完成态定义不清**：只折叠不收纳，用户仍可能觉得任务没有完成。

### 9.2 待补数据

- 目标家庭洗衣机/烘干机类型分布：洗烘一体机、独立洗衣机+烘干机、上开门/前开门、控制方式。
- 家庭衣物分布：T 恤、裤子、毛巾、内衣、袜子、床品、衬衫、裙装、厚外套占比。
- 用户可接受的自动化边界：是否允许机器人处理内衣、儿童衣物、宠物用品、床品。
- 用户对混洗、分拣、口袋异物的担忧排序。
- 目标家庭空间：洗衣机前方可达空间、折叠平面是否固定、收纳位置高度与距离。
- 竞品/替代方案：洗烘一体机自动投放、智能洗衣机 App、叠衣机、家政服务在用户心中的替代逻辑。

## 10. Go / No-Go 判定建议

### Go 条件

- 在兼容设备家庭中，能稳定完成“指定区域收集 → 投放洗烘一体机 → 启动 → 完成后取出 → 标准衣物折叠”的闭环。
- 单次任务非计划人工介入 ≤1 次，且异常可解释。
- 未发生误投放非衣物、门未锁启动、夹衣漏水、衣物损伤等信任破坏事件。
- 用户能明确感知减少了弯腰、走动、记事情和洗完后整理负担。

### No-Go 信号

- 只能演示把衣服放入滚筒，但无法保证不拿错、不夹衣、不选错程序。
- 折叠只在少量理想样衣上成立，无法限定可交付衣物清单。
- 每次异常都需要用户走到机器旁边重新处理。
- 设备兼容性依赖人工逐户调试，无法形成可运营清单。
- 用户仍需要自己分拣、检查口袋、转运、取出、再整理，机器人只完成中间一小段动作。

## 11. 结构化结论摘要

| 维度 | 结论 |
|---|---|
| 场景一句话定义 | 面向兼容洗烘一体机家庭的“指定区域脏衣收集 + 自动投放洗烘 + 干衣折叠叠放”家务闭环 |

| 最大风险 | 分拣/异物/误拾取缺失，以及叠衣指标未限定衣物类别导致用户预期失真 |
| 指标调整 | 原有触发指标保留；原有投放启动总成功率需拆成开门/投放/关门/程序/启动/状态确认子指标 |
| 待补证据 | 设备分布、衣物类别分布、用户混洗担忧、空间约束、竞品替代逻辑 |
