## 3. 结论先行

**核心用户价值不是“机器人能操作洗衣机”，而是用户能把洗衣这件事从脑子里移出去：不用到处捡衣服、不用判断家里机器能不能被操作、不用担心拿错/洗坏/夹衣/没启动、不用记得洗完取出，也不用在最后再重新整理一遍。**

所以 2 代洗衣需求应从单点动作升级为闭环任务：

> **触发任务 → 设备兼容确认 → 指定区域收集 → 分拣/异物预检 → 开门投放 → 关门锁定 → 程序选择与启动 → 洗烘状态监控 → 干衣取出转运 → 标准衣物折叠 → 叠放/收纳/交付 → 完成反馈。**

当前输入覆盖了触发、设备调研、收集、洗衣机投放启动、折叠，但仍需补齐四个会直接决定用户是否敢复用的信任门槛：

1. **误拾取与异物边界**：不能把干净衣、玩具、证件、耳机、纸巾等一起洗。
2. **分拣与洗涤程序匹配**：不能把深浅色、特殊材质、内衣外衣等混成一个黑箱。
3. **洗烘完成后的取出转运**：不能只启动机器，必须处理洗完后的干衣取出、残留、潮湿和转运。
4. **叠放/收纳完成态**：用户判断完成不是“折了一下”，而是能放到指定篮、平台或收纳位。

## 4. 建议功能架构与优先级

| 优先级 | 核心功能 | 用户价值定位 | 关键判断 |
|---|---|---|---|
| P0 | 多入口任务触发与状态反馈 | 让任务发起足够轻、过程足够可控 | 保留语音/APP/定时，但必须共用同一任务状态机 |
| P0 | 家庭环境与设备兼容门禁 | 先确认“这户能不能做”，避免现场失败 | 问卷只能预筛，必须加实机标定与兼容清单 |
| P0 | 指定区域收集与分拣预检 | 减少弯腰走动，同时不拿错、不洗坏 | 指定区域优先于全屋搜索；误拾取是红线 |
| P0 | 洗衣机操作与洗烘启动 | 把衣物安全放入并确认机器真的运行 | 原总成功率必须拆成开门/投放/关门/程序/启动 |
| P0/P1 | 洗烘完成取出与转运 | 用户不用记得洗完再处理 | 洗烘一体机是首版合理边界，独立洗烘转运后置 |
| P0/P1 | 标准衣物折叠与叠放/收纳 | 最终可见价值，决定用户是否认可 | “≥90%”必须限定衣物类别、平面、质量标准 |

## 5. 按指定字段输出的核心功能梳理

### 5.1 多入口任务触发与状态反馈

| 字段 | 梳理结论 |
|---|---|
| 用户价值 | 用户不用打开复杂入口，只要一句话、APP 点选或自动日程就能启动；同时能随时知道机器人听懂没有、做到哪一步、是否需要接管。 |
| 核心功能名称 | 多入口任务触发与统一状态反馈 |
| 功能描述 | 支持语音触发、APP 指定区域/叠放/收纳任务、智能体基于家庭成员习惯定时触发，并把任务状态统一反馈给用户。 |
| 功能性质 | P0 基础入口 + 信任基础；属于低硬件成本、高体验影响功能。 |
| 成本浮动空间建议 | 低到中：主要是语音/NLU、APP 交互、任务状态机与云端/本地智能体开发成本；硬件增量可控制在麦克风阵列、状态灯/扬声器等基础件。 |
| 关键部件参考建议 | 麦克风阵列、扬声器/蜂鸣器、状态灯/屏幕、APP 任务配置页、本地任务状态机、语音 ASR/NLU、家庭习惯策略模块。 |
| 材料性质需求 | 入口硬件应耐污、抗清洁剂轻微擦拭；外露按键/灯带需防水溅、防尘、易清洁。 |
| 功能规格需求 | 支持语音、APP、自动定时三类入口；支持指定收集区域、折叠平面、叠放/收纳位置；支持暂停、取消、继续、转人工确认。 |
| 智能化需求 | 意图识别、任务参数补全、家庭成员偏好学习、安静时段判断、设备空闲状态判断、异常原因解释。 |
| 核心参数/关键指标 | 语音唤醒率 ≥98%（5m 内）；意图识别准确率 ≥95%；端到端任务创建延迟 ≤2s；关键状态反馈延迟 ≤3s；异常反馈 ≤30s。 |
| 用户体验验证标准 | 用户在不查看说明书的情况下能发起任务；任务开始后能明确知道当前阶段；出现异常时能理解原因并选择下一步。 |
| 设计需求 1 | 语音触发必须确认任务对象和范围。 |
| 设计指标 1 | 常用语义覆盖“开始洗衣/收卧室脏衣/把烘干衣服叠好”等 ≥95%；歧义任务二次确认触发率 100%。 |
| 设计需求 2 | APP 必须允许用户指定区域与完成位置。 |
| 设计指标 2 | 任务参数完整率 ≥98%；任务执行前可修改/取消成功率 ≥99%。 |
| 设计需求 3 | 智能体定时不得变成打扰。 |
| 设计指标 3 | 自动触发误打扰率 ≤2%；夜间/有人休息/设备忙碌时不自动启动。 |
| 参考方案建议 | P0 用“用户主动触发 + 可配置日程提醒”；P1 再做衣物量/家庭成员习惯触发；P2 做主动洗护建议。 |
| 外观设计参考建议 | 用家电化、安静、低打扰的状态表达：柔和灯带 + 简短语音反馈；避免像工业机器人一样强提示。 |
| 优先级 | P0 |
| 后续可能性优化方向 | 从固定日程升级为“衣物量 + 家庭日程 + 天气 + 穿着习惯”的主动建议，但必须保留用户确认权。 |

### 5.2 家庭环境与洗衣/烘干设备兼容门禁

| 字段 | 梳理结论 |
|---|---|
| 用户价值 | 用户最关心“我家的洗衣机/烘干机到底能不能被机器人安全操作”，不想买回去才发现门打不开、按钮按不了或程序选不对。 |
| 核心功能名称 | 家庭环境与设备兼容性确认 |
| 功能描述 | 通过调研问卷收集洗衣机、烘干机、安装空间、门型、控制方式等信息，并在首次建图/标定时验证是否支持自动操作。 |
| 功能性质 | P0 安全门禁；决定是否开放后续自动洗衣能力。 |
| 成本浮动空间建议 | 中：问卷与规则库成本低，但设备适配库、实机标定、门体/按钮识别与 IoT/API 对接会带来中等持续成本。 |
| 关键部件参考建议 | 设备兼容数据库、型号识别规则、RGB-D/腕部相机、力控传感、门把手/旋钮/按钮识别算法、洗衣机 IoT/API 接口、空间测距模块。 |
| 材料性质需求 | 机器人与家电接触件需柔性、防刮、防滑；靠近洗衣机门圈/水汽区域的部件需耐潮、耐清洁剂、耐轻微高温。 |
| 功能规格需求 | 支持品牌/型号、前开门/上开门、洗烘一体/独立洗烘、控制面板形态、安装高度、前方可达空间、门开合范围、是否联网等字段采集。 |
| 智能化需求 | 问卷信息与视觉标定交叉校验；自动判断支持/不支持/需人工确认；不支持原因可解释。 |
| 核心参数/关键指标 | 设备信息采集完整率 ≥95%；兼容性判断准确率 ≥98%；实机标定通过后再开放自动执行；高风险误放行 0。 |
| 用户体验验证标准 | 用户能在购买/开通前知道自己家是否支持；不支持时知道是门型、空间、型号、控制方式还是安全原因。 |
| 设计需求 1 | 问卷不能只问“是否有洗衣机”，要问可操作要素。 |
| 设计指标 1 | 品牌/型号/门型/控制方式/安装空间 5 类关键字段完整率 ≥95%。 |
| 设计需求 2 | 首次使用必须做实机标定。 |
| 设计指标 2 | 开门、关门、控制面板/API、程序启动、门锁反馈 5 项标定通过率逐项记录。 |
| 设计需求 3 | 不支持家庭不能被强行进入自动执行。 |
| 设计指标 3 | 未通过兼容门禁时自动洗衣任务创建被拦截 100%，并给出原因。 |
| 参考方案建议 | 首版聚焦前置式洗烘一体机 + 固定安装空间 + 可识别门把手/IoT 控制；独立洗衣机+烘干机转运后置。 |
| 外观设计参考建议 | 标定过程要“家电安装向导化”：用图示/灯光/APP 引导用户拍摄门型和空间，降低技术感。 |
| 优先级 | P0 |
| 后续可能性优化方向 | 建立品牌型号兼容清单与众包标定库；与洗衣机厂商 IoT 协议打通，减少机械按键操作。 |

### 5.3 指定区域脏衣收集与分拣预检

| 字段 | 梳理结论 |
|---|---|
| 用户价值 | 用户希望减少弯腰、走动、到处捡衣服和催家人的负担，但更不能接受机器人拿错东西、把口袋异物一起洗、把干净衣/玩具/贵重物误投放。 |
| 核心功能名称 | 指定区域脏衣收集与分拣预检 |
| 功能描述 | 在卧室、沙发边、脏衣篮周边等指定区域收集可处理衣物，并做衣物/非衣物、干净/脏衣、特殊材质、明显异物风险的预检。 |
| 功能性质 | P0 主功能 + 安全红线；是用户敢不敢让机器人自动洗衣的关键。 |
| 成本浮动空间建议 | 中到高：视觉识别、机械臂抓取、柔性衣物操作和异物检测均会带来硬件与算法成本；建议先限定区域和衣物类型控制成本。 |
| 关键部件参考建议 | 移动底盘、RGB-D 相机、腕部相机、柔性夹爪/夹持末端、触觉/压力传感、称重或阻力检测、可移动脏衣篮、边缘 AI 识别模块。 |
| 材料性质需求 | 夹爪需软质、防滑、不勾丝、不染色；接触衣物材料需抗静电、可清洁、耐汗渍/水汽；脏衣篮模块需可拆洗、抗菌、透气。 |
| 功能规格需求 | 支持用户指定收集区域、禁区、目标脏衣篮；支持标准衣物识别、非衣物排除、明显硬物/鼓包/异常重量提示。 |
| 智能化需求 | 衣物实例分割、可抓取点评估、脏衣/非脏衣风险判断、异物风险检测、家庭成员/区域偏好学习、低置信度转人工确认。 |
| 核心参数/关键指标 | 指定区域脏衣召回率 ≥90%；误拾取率 ≤2%；非衣物误投放 0；禁区进入 0；高风险异物提示召回率 ≥90%（先限定大件/硬物）。 |
| 用户体验验证标准 | 用户能放心让机器人处理卧室/沙发等指定区域，且不需要事前把所有非衣物清空；低置信度时机器人会停下来问，而不是硬拿。 |
| 设计需求 1 | 收集范围必须可控，不能默认全屋乱找。 |
| 设计指标 1 | 用户指定区域内任务覆盖成功率 ≥90%；非指定区域抓取 0。 |
| 设计需求 2 | 误拾取是 P0 红线。 |
| 设计指标 2 | 玩具、证件、线缆、抱枕、干净挂置衣物等非目标物误投放 0。 |
| 设计需求 3 | 分拣能力先做风险拦截，不承诺全自动精细护理。 |
| 设计指标 3 | 特殊衣物/不确定衣物进入待确认篮或用户确认流程，误自动投放率 ≤1%。 |
| 参考方案建议 | P0 先做“固定区域 + 固定脏衣篮 + 日常混洗衣物”；P1 做深浅色/毛巾/床品分拣；P2 做精细面料与家庭成员分拣。 |
| 外观设计参考建议 | 脏衣收集模块应像家用洗衣篮而非工业料箱；干净/待确认/待人工处理可用颜色或分区清晰区隔。 |
| 优先级 | P0 |
| 后续可能性优化方向 | 建立家庭衣物库、成员衣物偏好、洗涤标签识别、口袋异物多模态检测，以及“本次只处理普通日常衣物”的智能筛选。 |

### 5.4 洗衣机开关门、投放、程序选择与启动

| 字段 | 梳理结论 |
|---|---|
| 用户价值 | 用户不只是要衣服进滚筒，更要确认没有夹衣、没损坏门、门已锁、程序没选错、机器真的开始运行。 |
| 核心功能名称 | 洗衣机操作与洗烘启动闭环 |
| 功能描述 | 完成开门、投放脏衣、关闭机门、开机、选择程序、启动洗衣/洗烘，并反馈启动状态。 |
| 功能性质 | P0 核心执行功能 + 安全门禁；原输入中的“投放-关门-开机-选择程序-启动 ≥90%”应拆成多个子指标。 |
| 成本浮动空间建议 | 高：涉及机械臂精细操作、力控、视觉确认、家电接口适配；若通过 IoT/API 选择程序，可降低机械按键/旋钮复杂度。 |
| 关键部件参考建议 | 6/7DoF 机械臂或专用开门机构、柔性夹爪、腕部相机、六维力/力矩或电流力控、门锁/门缝视觉检测、IoT/API 控制模块、设备状态读取模块。 |
| 材料性质需求 | 与门体/滚筒/衣物接触处需防刮、防滑、柔性包胶；靠近潮湿环境需耐水汽、防霉、防清洁剂腐蚀。 |
| 功能规格需求 | 支持前置式滚筒门开合、分批投放、滚筒内视觉确认、门缝夹衣检测、门锁确认、预设程序/API 启动。 |
| 智能化需求 | 门型识别、开门轨迹规划、柔性衣物投放规划、门缝/夹衣检测、程序匹配、启动状态识别、异常恢复策略。 |
| 核心参数/关键指标 | 开门成功率 ≥95%；投放成功率 ≥90%；门缝夹衣率 ≤1%；关门锁定确认率 ≥98%；程序选择正确率 ≥95%；启动确认成功率 ≥98%；门未锁启动 0。 |
| 用户体验验证标准 | 用户无需站在洗衣机旁监督；如果门卡住、夹衣、过载、程序不确定，机器人能停止并说明，不会强行启动。 |
| 设计需求 1 | 原“总成功率 ≥90%”必须拆分归因。 |
| 设计指标 1 | 开门/投放/关门/程序/启动五段分别记录成功率和失败原因，不能只报总数。 |
| 设计需求 2 | 启动前必须确认门锁和夹衣风险。 |
| 设计指标 2 | 门未锁、门缝夹衣、衣物外露时启动拦截率 100%。 |
| 设计需求 3 | 程序选择以“不洗坏”为优先。 |
| 设计指标 3 | 标准程序选择正确率 ≥95%；不确定衣物程序转用户确认 100%。 |
| 参考方案建议 | P0 固定“标准混合洗/洗烘一体预设程序”；优先走 IoT/API 启动，机械按键作为兼容补充；复杂程序后置。 |
| 外观设计参考建议 | 末端执行器要有柔性包覆与圆角，避免用户看到“硬机械臂怼家电”；启动状态可用简洁灯效和 APP 时间轴表达。 |
| 优先级 | P0 |
| 后续可能性优化方向 | 与洗衣机品牌协议深度打通，支持水温、转速、洗涤剂投放、烘干强度等程序参数自动匹配。 |

### 5.5 洗烘完成监控、干衣取出与转运

| 字段 | 梳理结论 |
|---|---|
| 用户价值 | 用户真正想省掉的是“洗完还要记得取、转、晾/烘、再整理”的后半段负担；否则机器人只是把家务推迟了。 |
| 核心功能名称 | 洗烘完成监控与干衣取出转运 |
| 功能描述 | 监控洗烘完成状态，确认衣物可取出，打开门、取出干衣、检测滚筒残留，并转运到固定折叠平面。 |
| 功能性质 | P0/P1 交界：若承诺完整洗衣闭环，取出转运应进入 P0；若首版只做投放启动，可作为 P1，但需明确不完整。 |
| 成本浮动空间建议 | 高：干/湿衣物取出涉及柔性物体、重量变化、滚筒深处抓取、掉落污染、温湿度判断；建议用洗烘一体机和固定折叠台降低复杂度。 |
| 关键部件参考建议 | 机械臂、长行程柔性夹爪、腕部相机、滚筒内照明/视觉、温湿度传感、重量/拉力检测、可移动转运篮、固定折叠台定位标记。 |
| 材料性质需求 | 抓取/转运部件需耐热、耐潮、防染色、易清洁；干净衣物接触面需抗菌、低摩擦/不勾丝、无尖锐边。 |
| 功能规格需求 | 支持读取洗烘完成状态、开门散热、分批取衣、滚筒残留检测、掉落检测、转运到固定平面；潮湿衣物不得进入折叠。 |
| 智能化需求 | 完成状态识别、干燥程度判断、衣物残留检测、单件/多件抓取策略、掉落恢复、热/湿风险提示。 |
| 核心参数/关键指标 | 完成状态识别准确率 ≥98%；滚筒残留率 ≤2%；衣物掉落污染率 ≤1%；潮湿衣物误折叠率 ≤2%；异常反馈 ≤30s。 |
| 用户体验验证标准 | 用户不需要听到洗衣机结束提示后自己去取；机器人能把可折叠衣物送到固定位置，未干/异常时主动说明。 |
| 设计需求 1 | 洗烘完成必须可判断，而不是按时间估计。 |
| 设计指标 1 | 设备状态/API/视觉/温湿度至少两类信号交叉确认；完成识别准确率 ≥98%。 |
| 设计需求 2 | 滚筒内不能遗留衣物。 |
| 设计指标 2 | 滚筒残留检测覆盖率 100%；任务结束滚筒残留率 ≤2%。 |
| 设计需求 3 | 未干或高温衣物不能直接折叠。 |
| 设计指标 3 | 潮湿衣物误折叠率 ≤2%；高温/潮湿状态进入等待或提示流程。 |
| 参考方案建议 | P0 绑定洗烘一体机 + 固定折叠台；独立洗衣机到烘干机的转运作为 P1/P2，且需限定两机距离和相对位置。 |
| 外观设计参考建议 | 转运篮/折叠台外观应像家庭洗衣收纳组件，建议可拆洗、可隐藏、与家装/洗衣区融合。 |
| 优先级 | P0/P1（取决于首版是否承诺完整闭环；建议作为 P0 验证项） |
| 后续可能性优化方向 | 支持独立洗烘设备之间的短距离转运、晾晒架/烘干架协同、按家庭成员分类转运。 |

### 5.6 标准衣物折叠、叠放与收纳交付

| 字段 | 梳理结论 |
|---|---|
| 用户价值 | 折叠是最可见的价值点，用户会用“是不是像整理过、能不能直接收起来”判断机器人是否真正减负。 |
| 核心功能名称 | 标准衣物折叠与叠放/收纳交付 |
| 功能描述 | 在固定平面上，对从烘干机取出的标准衣物进行摊平、识别、折叠、堆叠，并放到指定篮/收纳台/交付位置。 |
| 功能性质 | P0/P1 主体验功能；首版必须限定衣物类别和完成态，不应承诺任意衣物。 |
| 成本浮动空间建议 | 高：柔性物体折叠对机械臂、夹爪、视觉、平面工装要求高；可通过固定折叠台、标准衣物类别和半结构化夹具降低成本。 |
| 关键部件参考建议 | 双臂或单臂+折叠工装、柔性夹爪、真空/夹持混合末端、顶视相机、腕部相机、固定折叠平面、衣物类别识别模型、堆叠稳定检测。 |
| 材料性质需求 | 折叠平面需低摩擦但不打滑、抗静电、不勾丝、可清洁；夹爪需软触感、不留压痕、不掉色；收纳篮需透气、抗菌、可拆洗。 |
| 功能规格需求 | 首版支持 T 恤、毛巾、长裤、睡衣等标准衣物；支持单件分离、摊平、折叠、堆叠；不支持衣物进入待人工处理。 |
| 智能化需求 | 衣物类型识别、姿态估计、边角/袖口/裤腿定位、折叠策略生成、堆叠稳定判断、家庭成员/类别分堆偏好学习。 |
| 核心参数/关键指标 | 标准衣物折叠成功率 ≥90%；单件分离成功率 ≥85%；摊平后可折叠率 ≥90%；堆叠倒塌率 ≤2%；用户可接受评分 ≥4/5；损伤 0。 |
| 用户体验验证标准 | 用户看到的结果应能直接放入收纳篮或衣柜外部指定位置；用户不需要重新大面积返工；不支持衣物被清晰分出。 |
| 设计需求 1 | “≥90% 折叠成功率”必须限定样本范围。 |
| 设计指标 1 | 按 T 恤/毛巾/长裤/睡衣分别统计折叠成功率，不能混成一个平均值。 |
| 设计需求 2 | 折叠前必须完成摊平和单件分离。 |
| 设计指标 2 | 单件分离成功率 ≥85%；摊平可折叠率 ≥90%；多件缠绕时转异常处理。 |
| 设计需求 3 | 叠放/收纳才是用户完成态。 |
| 设计指标 3 | 折叠后成功放入指定位置 ≥95%；堆叠倒塌率 ≤2%；用户无需重新整理比例 ≥80%（试点口径）。 |
| 参考方案建议 | P0 固定折叠平面 + 标准衣物 + 指定收纳篮；P1 支持按类别/成员分堆；P2 再做直接入柜、抽屉开合和复杂衣物。 |
| 外观设计参考建议 | 折叠台/收纳模块应可折叠、可隐藏、可清洁；避免占据大量家庭公共空间；干净衣物区域和脏衣区域需视觉上分开。 |
| 优先级 | P0/P1；若主卖点包含“叠衣”，则 P0 必须至少打穿标准衣物闭环。 |
| 后续可能性优化方向 | 衬衫、裙装、内衣袜子、床品、厚外套等复杂衣物；按家庭成员、衣柜分区、季节和穿着频率进行智能收纳。 |

## 6. 跨功能设计需求与系统指标

### 6.1 建议保留并重构的核心指标

| 指标组 | 建议指标 | 说明 |
|---|---|---|
| 触发 | 语音唤醒率 ≥98%（5m 内）；意图识别 ≥95%；端到端任务创建 ≤2s | 保留原输入指标，但只代表入口体验 |
| 状态反馈 | 关键状态反馈 ≤3s；异常反馈 ≤30s | 用户放心的关键是过程可见 |
| 设备兼容 | 设备信息采集完整率 ≥95%；兼容判断准确率 ≥98%；高风险误放行 0 | 问卷 + 实机标定双门禁 |
| 收集/预检 | 指定区域脏衣召回 ≥90%；误拾取 ≤2%；非衣物误投放 0；禁区进入 0 | “不拿错”比“多拿一点”更关键 |
| 投放启动 | 开门 ≥95%；投放 ≥90%；关门锁定 ≥98%；程序选择 ≥95%；启动确认 ≥98% | 拆分原总成功率，便于定位失败 |
| 洗烘完成 | 完成状态识别 ≥98%；滚筒残留 ≤2%；潮湿衣物误折叠 ≤2% | 补齐输入中未定义的后半段 |
| 折叠叠放 | 标准衣物折叠 ≥90%；堆叠倒塌 ≤2%；用户可接受评分 ≥4/5 | 必须限定衣物类别和质量标准 |
| 用户价值 | 单次任务非计划人工介入 ≤1 次；任务复用率；弯腰/走动/记忆负担下降 | 证明不是技术演示，而是真减负 |

### 6.2 三条必须写入 PRD 的红线

1. **门未锁 / 夹衣 / 设备异常不得启动。**
2. **非衣物、贵重物、儿童/宠物相关风险不得自动投放。**
3. **不支持衣物和不兼容设备必须进入解释/确认流程，不得伪装成可自动处理。**

## 7. P0 / P1 / P2 范围建议

### P0：首版必须打穿

- 语音 / APP / 定时触发统一任务状态机。
- 问卷 + 实机标定确认设备兼容。
- 指定区域或固定脏衣篮收集，不做全屋无边界搜索。
- 标准日常混洗衣物，特殊衣物进入待确认。
- 前置式洗烘一体机开门、投放、关门、程序启动、状态确认。
- 洗烘完成后取出干衣并转运到固定折叠平面。
- 标准衣物折叠与放入指定篮/平台。
- 关键异常可解释、可暂停、可人工接管。

### P1：体验增强

- 家庭成员习惯学习：时间窗、衣物量、房间优先级、安静时段。
- 深浅色/毛巾/床品等常见分拣。
- 口袋异物、硬物、纸巾风险检测增强。
- 独立洗衣机与烘干机之间的短距离转运，但限定两机布局。
- 折叠后按类别/家庭成员分堆。

### P2：平台化能力

- 任意房间开放式收集。
- 精细面料护理、衬衫、裙装、厚外套等复杂衣物折叠。
- 直接入柜收纳、抽屉开合、衣柜分区识别。
- 多品牌多形态洗衣机/烘干机深度兼容。
- 基于天气、家庭日程、穿着历史的主动洗护建议。

## 8. 用户体验验证标准

建议用 5 类试点任务验证，而不是只看实验室单步成功率：

1. **轻触发**：用户能在 2 秒内发起任务，并在 3 秒内看到状态确认。
2. **少接管**：单次完整任务非计划人工介入 ≤1 次。
3. **不出红线事故**：误投放非衣物、门未锁启动、夹衣漏水、衣物损伤、儿童/宠物干扰导致危险均为 0。
4. **结果可收纳**：标准衣物折叠后无需大面积返工，用户可接受评分 ≥4/5。
5. **敢复用**：试点用户在完成 3 次任务后仍愿意继续开启自动洗衣/叠衣任务。

## 9. 需要后续补充的证据

- 目标家庭洗衣机/烘干机类型分布：洗烘一体机、独立洗衣机+烘干机、前开门/上开门、联网能力。
- 家庭衣物类别分布：T 恤、裤子、毛巾、内衣、袜子、床品、衬衫、裙装、厚外套占比。
- 用户对混洗、分拣、口袋异物、衣物损伤、隐私衣物处理的担忧排序。
- 洗衣区空间：洗衣机前方可达空间、门打开半径、折叠平面位置、收纳位置高度。
- 竞品/替代方案：智能洗衣机 APP、自动投放洗衣机、叠衣机、家政服务在用户心中的替代逻辑。
- 质量风险数据：门体损伤、漏水、夹衣、异物、机械臂碰撞、布料损伤等 FRR/FFR 口径。

## 10. 一句话产品定义建议

> **2代洗衣功能应定义为：面向兼容洗烘一体机家庭的“指定区域脏衣收集 + 安全投放洗烘 + 干衣取出 + 标准衣物折叠叠放”的家务闭环；首版不承诺任意家庭、任意设备、任意衣物、直接入柜。**
