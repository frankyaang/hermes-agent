# 标准输出模板

## 0. 问题回答

先直接回答用户真正问的问题。

要求：

- 用总结性答复先给“总”
- 不能一上来只堆表
- 但这部分不能脱离后文证据

## 1. 分析对象与证据边界

必须包含：

- 分析目标表
- 分析对象表
- 目标展开后的特征图
- 特征暴露表
- 特征覆盖缺口表
- 易遗漏特征观察表

要求：

- 先按目标把相关特征尽量暴露出来
- 明确哪些是直连强证据、直连弱证据、代理证据、无证据
- 这部分的作用是防止数据被遗漏、结论变薄

## 2. 一级结论树

必须用表格列出：

- 一级结论
- 当前回答
- 关键支撑特征
- 证据强度
- 是否可继续下钻

要求：

- 这是“分”的总目录
- 后文递归论证必须和这里一一对应

## 3. 递归论证

这一节是主体，按一级结论分别展开。

### 3.x 一级分结论

每个一级分结论必须满足：

- 一级结论前置表格
- 一级结论文本
- 子结论可继续展开

### 子结论规则

- 子结论可以继续包含子结论
- 是否继续往下拆由证据决定
- 证据不够时必须显式停住，并写清：
  - 当前结论
  - 证据来源
  - 证据强度
  - 当前仍缺什么

### 推荐递归模块

- `VOC` 证据与论证
- 问卷证据与论证
- 定性访谈证据与论证
- 智能性拆维论证
- 跨源综合证据与论证
- 价值支柱论证

## 4. 反证 / 缺口 / 风险

必须包含：

- 当前不能下满结论的地方
- 冲突与风险表

要求：

- 不能把风险隐藏在叙事里
- 要明确哪些地方当前只能做方向判断

## 5. 下一步行动（5W2H）

这一节必须是表格，不再只是自然语言建议。

| Why | What | Who | When | Where | How | How much / 预期投入或样本门槛 |
| --- | --- | --- | --- | --- | --- | --- |

要求：

- 行动数不固定
- 只纳入真正重要的行动
- `Who` 可以是用户、研究团队、产品经理、数据工程，也可以是具体智能体 / Agent
- `How` 需要结合当前记忆、系统 skill 能力、知识库与现有产物

## 6. 数据能力声明与附录

这一节放在最后，作为说明性内容，不抢在主结论前面。

至少包含：

- 数据能力声明表
- VOC 样本说明
- 原始证据追溯
- 当前可以下结论的事
- 附录索引

| 模块 | 支持度 | 使用的数据源 | 用通俗话解释当前能看到什么 / 看不到什么 |
| --- | --- | --- | --- |
| VOC 分析 | 支持 / 部分支持 / 不支持 |  |  |
| 用户画像 | 支持 / 部分支持 / 不支持 |  |  |
| 房屋与环境 | 支持 / 部分支持 / 不支持 |  |  |
| 购买旅程 | 支持 / 部分支持 / 不支持 |  |  |
| 使用旅程 | 支持 / 部分支持 / 不支持 |  |  |
| 概念验证 | 支持 / 部分支持 / 不支持 |  |  |

要求：

- 面向不了解数据库的读者，不能只写库名或技术字段
- 每一行都要说明：
  - 结论来自哪些材料
  - 覆盖到哪些对象 / 周期
  - 为什么是 `支持 / 部分支持 / 不支持`
