# 机器人产品 VOC 与调研问卷分析通用框架

## 1. 适用范围

这份框架用于各类机器人产品，例如：

- 扫地机器人
- 擦窗机
- 割草机器人
- 泳池机器人
- 商用清洁机器人

固定原则：

- 先 `VOC`
- 再 `调研问卷`
- 最后 `跨源综合`
- `数据能力声明` 放在最后，作为证据说明附录

## 2. 固定流程

1. `Preflight`
2. `Bundle Generation`
3. `VOC 单源统计分析`
4. `调研问卷单源统计分析`
5. `跨源综合判断`
6. `数据缺口与下一步建议`
7. `数据能力声明与证据说明`

## 3. Preflight

先确认：

- 品类是什么
- 本品和竞品对象是什么
- 时间范围是什么
- 当前数据块支持哪些模块

`Preflight` 阶段仍然要先生成支持度判断，但正式报告默认把这张表放到最后，作为阅读辅助说明，而不是开篇主体。

推荐直接使用脚本：

```bash
cd skills/domain/robot-product-voc-survey-insight
python3 scripts/run_multisource_preflight.py
```

标准一键产物入口：

```bash
cd skills/domain/robot-product-voc-survey-insight
python3 scripts/generate_insight_bundle.py
```

## 4. VOC 单源统计分析

必须至少包括：

1. 样本盘点
2. 情感分布
3. 完整标签表
4. 负评问题拆解
5. 同周期本品 vs 竞品差异
6. 前后代差异
7. 同价格带差异
8. 周度较过往变化

每个子模块都必须有：

1. 统计表
2. 结论
3. 差异点

默认强调：

- 不同产品之间的 VOC 差异
- 不同代际之间的 VOC 差异
- 不同周期之间的 VOC 差异

默认不建议单独做脱离对比关系的“VOC 特征分析”。

对于负评，尽量进一步拆到：

1. 细分场景
2. 工况
3. 关联物品
4. 图片证据
5. 时间变化

## 5. 调研问卷单源统计分析

建议按下面顺序：

1. 样本有效性
2. 用户画像
3. 房屋与环境
4. 购前替代方式与痛点
5. 购买旅程
6. 使用旅程
7. 概念验证

规则：

- 有题就分析
- 没题就明确写 `不支持`

## 6. 跨源综合判断

只在 `VOC` 和 `问卷` 两边都完成后再做。

必须至少包括：

1. 跨源一致问题
2. 跨源一致优势
3. 冲突信号
4. 优先级矩阵

## 7. 核心差异判定

默认门槛建议：

- `sample_gate >= 300`
- `tag_gate >= 30`
- `delta_pp >= 2`
- `index >= 1.5`

不满足门槛的内容，不进入“核心差异”。

## 8. 数据能力声明与证据说明

放在报告最后，目的是帮助不了解数据库的读者理解证据边界。

写法要求：

- 用业务语言解释支持范围，少用库表术语。
- 说明：
  - 结论基于哪些数据源
  - 覆盖了哪些产品 / 波次 / 周期
  - 当前缺口是什么
  - 哪些只能做方向判断，不能做最终定案
