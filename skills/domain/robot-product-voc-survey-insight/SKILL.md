# 看用户

Canonical ID：`robot-product-voc-survey-insight`
中文名：`看用户`
用途：把机器人产品，尤其清洁机器人场景里的用户判断读清楚、讲清楚、收成产品定义输入。

这不是旧的“VOC 单源 + 问卷单源 + 跨源综合” skill。

它的主任务固定是：

- 讲清用户为什么买
- 讲清用户为什么持续认可
- 讲清用户为什么失望
- 讲清用户为什么改选
- 讲清下一代该补什么定义

最高约束固定为：

**所有输出都必须像一个会做产品的人在读用户。**

## 快速路径

1. 先确认当前是不是“看用户”问题，而不是单纯做标签统计或数据清洗。
2. 先把评论、质量和竞品材料翻译成 `JudgmentUnit（用户判断单元）`，不要直接从标签播报开始。
3. 以 `Top15 fact pool（Top15 事实池）` 为事实底座。
4. 先做 `表1：Top15 场景穿透与时间序列风险`。
5. 再做：
   - `模块2：Top15 代际强对比`
   - `模块3：Top15 竞争强对比`
   - `表4A / 表4B：FRR / FFR 风险校正`
6. 最后再写：
   - `PM 总结提炼`
   - `用户还在用这两把尺子判断 X/T 系`
   - `PM 战略行动指南`

## 默认方法骨架

固定使用这条链：

1. `JudgmentUnit（用户判断单元）`
2. `Top15 fact pool（Top15 事实池）`
3. `Top15 场景穿透`
4. `当前代完整 Top15 驱动代际对比`
5. `当前代完整 Top15 驱动竞品对比`
6. `FRR / FFR 风险校正`
7. `PM 总结与定义输入`

绝不能反过来：

- 先写结论
- 再找标签和 quote 去补证据

## 必须遵守的硬约束

- 逻辑上始终只有**一份唯一 VOC 报告**，不分本品稿 / 竞品稿 / 质量稿。
- `X / T / 服务链路` 是稳定观察对象，但**当期任务定义动态生成**。
- `Top15` 是事实池，也是前台主展示；模块1、模块2、模块3都必须完整展开 Top15，不能只挑代表行。
- `表1` 和 `表1A` 不再分开读，默认合并成唯一穿透表。
- `FRR / FFR` 只做证据增强与风险校正，不抢 VOC 主叙事。
- 竞品判断必须解释**替代逻辑**，不能写成参数输赢或胜负播报。

## 默认报告结构

默认输出固定为：

1. `执行摘要`
2. `X 系专场`
3. `T 系专场`
4. `服务链路专场`
5. `PM 战略行动指南`

其中：

- `X 系`、`T 系` 作为一级观察对象保持稳定
- 每期都要重新生成：
  - `当期任务定义`
  - `主买点`
  - `主认可点`
  - `主断点`
  - `主改选点`
  - `定义输入`

## X/T 专场固定结构

每个专场固定包含：

1. `PM 总结提炼`
2. `用户还在用这两把尺子判断 X/T 系`
3. `表1：Top15 场景穿透与时间序列风险`
4. `模块2：Top15 代际强对比`
5. `模块3：竞争强对比`
6. `表4A / 表4B：FRR / FFR 风险校正`

### 1. PM 总结提炼

只讲主选择逻辑：

- 为什么买
- 为什么持续认可
- 为什么失望
- 为什么改选
- 下一代该补什么

### 2. 用户还在用这两把尺子判断 X/T 系

这层不是补漏。

它只负责讲：

- 主线之外，用户还会顺手用哪两三把稳定尺子判断这个系列

### 3. 表1：Top15 场景穿透与时间序列风险

表1 是唯一穿透主表。

每一行都必须同时读到：

- `Top15 核心指标`
- `当前代提及率`
- `周度变化`
- `一级产品维度`
- `用户任务翻译`
- `强关联场景`
- `强关联物品`
- `PM 场景破译与风险定性`
- `真实 VOC 原声与定义输入`

表1 必须完整展示 15 行，不允许裁剪。

解释力弱的项也保留，但要明确写成：

- `顺手加分项`
- `背景信号`
- `非主战局依据`

不要硬拔成主买点。

### 4. 模块2：Top15 代际强对比

代际对比必须以**当前代完整 Top15** 为锚。

固定回答：

- 这一代是不是把这条体验往前推了
- 老问题是修掉了、变轻了、转移了，还是还没修掉
- 用户会在哪个瞬间感知到这一代变了

不要写成统计观察口气。

要写成：

- 这一代终于把什么从“偶尔成立”推到了“用户会主动提起”
- 这一代虽然更强了，但什么地方还会把用户拉回接管
- 这条体验两代都在做，但这一代更不容易在关键位置掉链子

### 5. 模块3：竞争强对比

竞争章节固定顺序：

1. `竞争总判断`
2. `每个竞品一张独立表`
3. `竞争综合收口`

每张独立表必须按**当前代完整 Top15** 逐行展开。

固定列：

- `锚点 Top15 指标`
- `本品当前代表现`
- `竞品同名指标表现`
- `同任务补充说明`
- `用户任务翻译`
- `用户为什么会改选`
- `PM 对打判断`

规则固定为：

- 竞品列先写**同名指标**
- 任务层补充只放在 `同任务补充说明`
- 竞争判断要解释竞品在哪条任务上形成替代
- 不要写“这一票”“投给谁”“还守得住”这种胜负播报

### 6. 表4A / 表4B：FRR / FFR 风险校正

- `FRR`：判断问题是否已经把用户推走
- `FFR`：判断问题是否已经变成可靠性风险

表4 固定职责：

- 校正风险
- 不重写主结论

评论侧表达只能使用：

- `用户侧已显性`
- `用户侧已冒头`
- `用户侧暂未放大`

风险层级只能使用：

- `常规波动`
- `重点关注`
- `高风险`
- `生死线`

语气始终保持成熟期品类 PM 视角。

## 文风规则

所有 `PM 场景破译与风险定性 / PM 代际判断 / PM 对打判断` 都必须：

- 讲用户会在什么瞬间更相信它
- 讲用户会在什么位置重新犹豫
- 讲用户为什么会返工、接管、改选
- 讲竞品到底在抢哪条任务

前台不解释：

- 系统有没有命中证据
- 系统为什么没找到 quote
- 标签层怎么映射

## 明确禁止的反模式

以下表达默认禁止出现：

- `暂无稳定 VOC 原声可对撞`
- `这一票`
- `投给`
- `改票`
- `还守得住`
- `暂时不会因为`
- `更容易被接住`
- `还要继续确认`
- `更像同一条任务的不同说法`
- `更轻松、更稳、更成熟`
- 任何“系统没找到 / 系统没有匹配到”式表达

遇到这类情况，要改写成：

- 用户侧现在显性到什么程度
- 这条体验在用户心里是主战役、次级支撑，还是背景信号
- 竞品在这条任务上是主抢点、次级切口，还是暂时没形成记忆

## 最小输入

至少需要：

- `category_name`
- `analysis_goal`
- `product_scope`
- `time_scope`
- `VOC` 数据

可选增强输入：

- `FRR / FFR`
- 竞品数据
- 服务链路数据
- 调研问卷

如果没有问卷，也可以完整运行“看用户”主链。

## 何时下钻其他资源

- 如果任务需要更完整的离线评测与优化，优先读取本技能包内的 `references/`、`examples/` 与用户显式提供的数据资产。
- 如果任务需要实际生成唯一 VOC 正式稿，优先使用本技能包的 `scripts/generate_insight_bundle.py` 或 `scripts/run_multisource_preflight.py`，并通过参数显式传入输入数据。

## 默认交付

默认交付应优先是：

- 唯一 VOC 报告正文
- 结构化结论
- 可回挂的证据表
- 明确的定义输入

而不是：

- 只做标签统计
- 只做问卷摘要
- 只做分源拼盘
