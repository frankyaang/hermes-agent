# Humanizer-zh: 中文自然润色

用于中文文本的润色、改写、去模板感、降低 AI 腔。用户可能不会说 skill 名字，而是说：

- "这段太 AI 了，帮我改自然点"
- "帮我润色这封邮件"
- "这段周报太虚了，改实一点"
- "发给老板，语气别太冲"
- "这句话改得像人话一点"
- "别这么官方，改得自然一点"

## 默认体验

- 不要默认告诉用户你使用了 Humanizer-zh。
- 短文本：直接给修改后文本。
- 长文本：给修改后文本，最多附一句改动说明。
- 文件编辑：优先用 targeted patch，保留 Markdown 结构、代码块、链接和表格。
- 用户要求解释时，才输出诊断、评分或逐条改动清单。
- 如果没有待编辑文本、文件路径或明确编辑对象，先简短询问要修改哪段。

## 边界

- 只优化表达，不协助欺骗 AI 检测器、学术造假、虚假署名或规避审查。
- 高风险文本只做保守润色：客户邮件、赔偿承诺、公告、合同、财务、法律、学术提交。
- 不新增事实、承诺、责任归因、截止时间、金额或产品能力。
- 不把明确判断磨平成空泛表述；用户原本的观点和风险提示要保留。

## 保真清单

改写前先标记这些内容，改写后逐项核对：

- 数字、金额、百分比、日期、版本号
- 产品名、公司名、人名、地名、专有名词
- 结论、判断、风险、责任人、截止时间
- 对外承诺、赔偿、交付范围、法律或财务含义
- Markdown 标题、表格、链接、代码块、命令、参数

如发现原文信息不完整，不要补编。可以把不确定点留作一句简短提示。

### 保真示例

原文：

> 5月15日，X100 项目成本下降 12%，预计 6月30日完成第二轮验证。

用户要求："改自然点。"

可改为：

> X100 项目在 5月15日确认成本下降 12%，第二轮验证预计 6月30日完成。

必须保留：`5月15日`、`X100`、`12%`、`6月30日`、`第二轮验证`。不要新增完成承诺、责任人或额外收益。

## 编辑强度

默认按中度保守处理。

- 轻改：修病句、删套话、清理连接词，结构基本不动。
- 中改：重排句子，让表达更顺、更具体，保留事实和判断。
- 重写：只有用户明确要求时使用，保留原意后重新组织表达。

正式材料默认轻改或中改；个人表达、公众号、演讲稿、营销文案可以更有节奏。合同、公告、客户投诉、赔偿邮件默认轻改。

## 常见 AI 腔

重点清理这些模式：

- 过度拔高意义：标志着、体现了、至关重要、关键作用、深远影响、不断演变的格局。
- 宣传腔：赋能、打造、闭环、抓手、生态、标杆、引领、全面提升、强势驱动。
- 空泛积极结尾：未来可期、持续发力、迈向新高度、开启新篇章。
- 模糊归因：专家认为、业内人士指出、相关数据显示、多个来源表明。
- 机械结构：首先/其次/最后，三段式排比，"不仅...还..." 过密。
- 软化过度：可能会、一定程度上、具有一定、可以说是、值得注意的是。
- 解释太满：把读者已经懂的背景重新铺一遍。
- 句式太整齐：每句长度类似，每段都像模板。

## 改写方法

1. 先判断场景：周报、邮件、IM、PRD、README、营销文案、学术文本或未知。
2. 保留事实骨架：数字、对象、动作、结论不动。
3. 删除套话和泛化评价，把抽象词改成具体动作。
4. 用自然连接替代模板连接；能直接并列就不要强行转折。
5. 让句子长短有变化。两项常常比三项更自然。
6. 结尾落在具体动作、判断或请求上，不要自动升华。
7. 最后做保真检查，确认没有改坏事实、格式或风险边界。

## 输出格式

短文本：

```text
修改后：
...
```

长文本：

```text
修改后：
...

我主要删掉了几处套话，保留了原来的事实和判断。
```

高风险文本：

```text
我会只优化表达，不新增事实、承诺或责任归因。

修改后：
...
```

用户要求诊断时再补充：

```text
主要问题：
- ...

改动说明：
- ...
```
