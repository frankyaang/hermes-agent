# 深度养马模式

## 概述

"深度养马"是把你的高频复杂任务沉淀为 Hermes 可复用技能的系统化流程。比喻来自养马：选一匹好马、规划赛道、备好草料、建好马厩，让它稳定跑、持续进化。

每个比喻都有对应的真实工作动作：
- **选马** → 识别值得沉淀的任务
- **定赛道** → 明确技能边界、输入输出
- **备草料** → 收集 Hermes 运行所需的知识和材料
- **搭马厩** → 起草并注册 SKILL.md
- **试跑** → 用真实案例验证技能
- **复训** → 根据反馈优化技能
- **挂牌使用** → 正式接入工作流
- **后续复用与持续喂养** → 建立长期迭代机制

8 个阶段按序推进，但允许在"试跑→复训"之间多轮循环。

## 触发场景

**使用此技能，当用户说：**
- "深度养马"、"开始养马"、"帮我训练 Hermes"
- "创建技能"、"新建技能"、"沉淀一个能力"
- "把这件事变成技能"、"让 Hermes 学会 X"
- "我每次都要做 X，能不能让 Hermes 记住"

**不使用此技能：**
- 用户只是想直接用现有技能（用 `skills_list` + `skill_view`）
- 一次性临时任务，沉淀价值低
- 用户已明确知道如何写 SKILL.md，只需要工具操作

---

## 阶段一：选马（识别值得沉淀的任务）

**目标：** 判断这件事值不值得变成技能。技能的价值来自可复用性——用一次就扔的不值得养马。

**向用户询问：**
1. 这件事你大概多久做一次？（每天 / 每周 / 每月）
2. 每次大概花你多少时间？
3. 做这件事时，你在 Hermes 里是每次重新说一遍背景，还是有固定的步骤？
4. 这件事有没有清晰的"输入"和"输出"？还是每次情况都不一样？

**输出：选马卡**

```
【选马卡】
任务名称：___
执行频率：___（每天 / 每周 / 月均 N 次）
单次耗时：___
当前痛点：___（每次要重新说背景 / 步骤繁琐 / 容易出错）
沉淀价值：___ （高 / 中 / 低）
推荐行动：___ （值得养马 / 暂缓 / 合并到已有技能）
```

**判断准则：**
- 频率 ≥ 每周一次 且 有稳定步骤 → 高价值，进入阶段二
- 频率低但步骤极复杂 → 中价值，建议先试跑一次再决定
- 每次差异大、无规律 → 暂缓，记录问题但不立刻沉淀

---

## 阶段二：定赛道（明确技能边界）

**目标：** 用一张清单把技能"说清楚"——谁用、给什么、出什么。边界不清的技能跑不稳。

**向用户询问：**
1. 这个技能的触发词是什么？（用户会怎么叫出它？）
2. 输入是什么格式？（文字描述 / 文件 / 链接 / 数据表 / 截图）
3. 期望输出是什么？（Markdown 报告 / 结构化 JSON / 直接回复 / 操作某个工具）
4. 有没有"不应该做"的事？（边界外的请求怎么处理？）
5. 使用者是你自己，还是团队？

**输出：赛道卡**

```
【赛道卡】
技能名称（英文 slug）：___（lowercase，hyphens，≤ 64 chars）
中文展示名：___
触发词：___（例："分析 VOC"、"生成竞品报告"）
输入：___（格式 + 示例）
输出：___（格式 + 示例）
使用者：___ （仅你本人 / 团队）
范围边界：___（明确列出 2-3 件不做的事）
```

**注意：** 技能名称命名为 lowercase + hyphens，不超过 64 个字符，与 Hermes `skill_manage` 的约束一致。

---

## 阶段三：备草料（收集知识和材料）

**目标：** Hermes 是一匹聪明但需要喂料的马。这个阶段确认它需要哪些"草料"才能稳定完成任务。

**向用户询问：**
1. 有没有现成的模板、样例输出？（可以直接放进技能作为参考）
2. 有没有必须知道的领域背景？（产品定义、行业术语、评分规则）
3. 有没有要避免的常见错误？（你以前踩过的坑）
4. 依赖哪些工具或外部资源？（特定 URL / 数据库 / API）

**输出：草料清单**

```
【草料清单】
必要材料：
  - ___（必须提供，否则无法完成）
  - ___
可选材料：
  - ___（有更好，没有也能跑）
参考示例：
  - 样例输入：___
  - 样例输出：___
领域知识点：
  - ___
工具依赖：
  - ___
```

---

## 阶段四：搭马厩（起草并注册技能）

**目标：** 把前三个阶段的产出转化为一个正式的 Hermes SKILL.md，并通过 `skill_manage` 注册。

### Hermes 的行动清单（此阶段需调用工具）

1. 根据赛道卡和草料清单，起草 SKILL.md 正文。
2. 确认 frontmatter 格式合规：
   - `name`：≤ 64 chars，lowercase + hyphens
   - `description`：≤ 1024 chars，以 "Use when..." 开头
   - 包含 `version`、`author`、`license`、`metadata.hermes.tags`
3. 调用 `skill_manage(action='create', name=..., content=...)` 注册技能。
4. 确认注册成功，记录技能路径。

> **何时调用 skill_manage：** 当 SKILL.md 草稿经用户确认无误后，立即调用 `skill_manage(action='create', ...)` 写入。不要在用户还在修改意见时就写入。

> **何时只讨论，不写入：** 用户还在考虑触发词、边界等核心定义时，只讨论，不调用工具。

### 最小 SKILL.md 草稿模板

```markdown
---
name: your-skill-name
description: 'Use when the user says ___. 一句话描述技能行为。'
version: 1.0.0
author: Hermes Agent
license: MIT
metadata:
  hermes:
    tags: [tag1, tag2]
    related_skills: []
---

# 技能中文名

## 概述

一两句说明这个技能做什么、适用什么场景。

## 触发场景

- 用户说"___"时使用
- 不适用于：___

## 执行流程

1. 接收输入：___
2. 处理步骤：___
3. 输出结果：___

## 常见错误

1. ___

## 验证清单

- [ ] ___
```

把赛道卡和草料清单填入对应占位符，然后调用：

```python
skill_manage(action='create', name='your-skill-name', content='<完整 SKILL.md 内容>')
```

**输出：马厩卡**

```
【马厩卡】
技能名称：___
注册路径：~/.hermes/skills/___/SKILL.md
skill_manage 调用结果：___ （成功 / 错误信息）
当前版本：1.0.0
下一步：进入试跑阶段
```

---

## 阶段五：试跑（用真实案例验证）

**目标：** 立刻用一个真实案例调用新技能，检验它能不能按预期跑起来。沙盘演练不算数，要用真材实料。

**向用户询问：**
1. 你最近做过一次这类任务吗？能把当时的输入材料给我？
2. 你当时的期望输出是什么？（用来对比 Hermes 的实际输出）

**Hermes 的行动：**
1. 以新技能身份接收用户提供的输入。
2. 完整执行一遍技能流程。
3. 对比实际输出与草料清单中的样例输出。

**试跑提示词模板**（用户可直接发给 Hermes）：

```
我想测试一下刚创建的「[技能名称]」技能。
以下是真实输入材料：

[粘贴材料]

请按技能流程完整执行，不要跳步骤。执行完毕后输出试跑卡。
```

**输出：试跑卡**

```
【试跑卡】
输入样本：___（简短描述，非全文）
实际输出摘要：___
预期对比：___ （符合 / 部分符合 / 不符合）
发现问题：
  - ___
  - ___
建议修改：___ （进入复训 / 技能已可用）
```

---

## 阶段六：复训（优化技能）

**目标：** 根据试跑反馈修改技能，让它跑得更稳、输出更准。复训可以多轮。

**向用户询问：**
1. 试跑哪里不符合预期？（具体说哪一步）
2. 你希望输出有什么变化？
3. 有没有新的草料可以补充？

**Hermes 的行动：**
1. 根据反馈列出修改点。
2. 用户确认后，调用 `skill_manage(action='patch', name=..., old_string=..., new_string=...)` 更新技能。
3. 更新 `version`（patch 改第三位，feature 改第二位）。
4. 记录修改历史到复训卡。

> **何时调用 skill_manage patch：** 修改点确认后立即调用，不要积攒多个修改一次性改，容易冲突。

**用户反馈 → patch 示例：**

> 用户说：输出里没有"结论"部分，每次都要我自己补。

```python
# Hermes 定位原文、确认修改点后调用：
skill_manage(
    action='patch',
    name='voc-analysis',
    old_string='## 执行流程\n\n1. 汇总 NPS 评分',
    new_string='## 执行流程\n\n1. 汇总 NPS 评分\n4. 输出结论：用一句话总结最重要的发现。',
)
# 同步更新版本号：
skill_manage(action='patch', name='voc-analysis',
    old_string='version: 1.0.0', new_string='version: 1.0.1')
```

**输出：复训卡**

```
【复训卡】
复训轮次：第 N 轮
修改点：
  - [已改] ___
  - [已改] ___
当前版本：___
试跑结果：___ （达标 / 需要下一轮复训）
```

---

## 阶段七：挂牌使用（正式接入工作流）

**目标：** 技能合格后，正式确认调用方式，让它融入日常工作流。

**向用户询问：**
1. 技能的调用入口是什么？（在 Hermes 里怎么叫出来？）
2. 这个技能只有你用，还是要分享给团队？
3. 有没有需要人工确认的关键节点？（⚠️ 见下方边界说明）

**Hermes 的行动：**
- 确认技能已在 `skills_list` 中可见。
- 生成团队公告模板，让用户贴到飞书 / Notion / 工作群。

**团队公告模板：**

```
【新技能上线】[中文名] / /[skill-name]

用途：___
怎么用：在 Hermes 里说「[触发词]」，或输入 /[skill-name]。
适用场景：___
注意（需人工确认，不能直接用输出）：
  - ___
有问题或改进建议请 @[维护人]，会持续复训优化。
```

**输出：挂牌卡**

```
【挂牌卡】
技能名称：___
调用方式：/___（slash command）或直接说"___"
适用范围：___ （个人 / 团队）
人工确认点：___ （哪些决策必须人工核实，见下方边界说明）
接入工作流：___ （Notion SOP / 飞书文档 / 口头约定）
上线日期：___
```

---

## 阶段八：后续复用与持续喂养

**目标：** 技能不是一次性的。建立反馈通道，让它随使用经验持续进化。

**向用户确认：**
1. 多久回顾一次这个技能是否还适用？（建议每月一次）
2. 遇到技能跑歪了怎么处理？（直接说"复训 X 技能"触发复训流程）
3. 有没有计划推广给其他同事？

**输出：复用卡**

```
【复用卡】
技能名称：___
上线版本：___
计划复训周期：___ （每月 / 每季度 / 按需）
复训触发词：___ （例："复训 VOC 分析技能"）
推广计划：___ （仅自用 / 分享给 ___ 人）
下一次复盘时间：___
```

---

## skill_manage 调用时机汇总

| 阶段 | 操作 | 调用方式 |
|------|------|----------|
| 搭马厩 | 首次注册技能 | `skill_manage(action='create', name=..., content=...)` |
| 复训 | 更新技能内容 | `skill_manage(action='patch', name=..., old_string=..., new_string=...)` 或 `action='edit'` |
| 挂牌使用 | 确认技能存在 | `skills_list()` 验证可见性 |

**只讨论、不写入的情况：**
- 用户还在纠结技能名称或边界定义
- 草料清单尚未确认
- 试跑还没跑完

---

## 边界与人工确认点

⚠️ **以下场景必须标记为人工确认点，Hermes 给出建议但不做决策：**

- 涉及**资源投入**的判断（人力、预算、优先级）
- 涉及**权限或组织**的安排（谁能用、谁负责维护）
- 涉及**对外发布**的内容（客户报告、公开文档）
- 涉及**人事**的评价或决策

在挂牌卡中明确列出这些人工确认点，并在技能正文中用 `> ⚠️ 人工确认点：___` 标记。

---

## 常见错误

1. **选了不该养的马。** 一次性任务没有复用价值，强行沉淀只会浪费时间。选马阶段要诚实评估频率。

2. **赛道边界模糊。** "帮我分析用户数据"的边界太宽，技能会跑偏。要具体到"分析飞书问卷的 NPS 评分数据，输出 Markdown 报告"。

3. **草料不够就搭马厩。** 没有样例输出就开始写 SKILL.md，结果技能"能跑但跑不准"。先备好草料，再搭马厩。

4. **跳过试跑。** 直接挂牌的技能，第一次真实使用就踩坑。哪怕一个小案例也要跑一遍。

5. **复训积攒太多修改。** 每次试跑只改一两点，改完立刻 patch，不要攒到最后一起改。

6. **忘记标记人工确认点。** 技能涉及高风险决策时，没有告知用户需要人工核实，造成误用。
